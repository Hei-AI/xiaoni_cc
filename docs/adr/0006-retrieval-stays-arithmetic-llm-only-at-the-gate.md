# 召回的检索层保持确定性算术，LLM 只用在投递闸和 query 展开

斯坦福小镇（Generative Agents, arXiv 2304.03442）的检索是
`recency + importance + relevance` 三项等权归一，其中 **importance 由语言模型在记忆写入的
那一刻打分（1–10）**，检索本身是纯算术。我们抄它的**形状**，但不抄那次写入时的 LLM 调用。

**为什么不让模型打 importance：对她而言重要性是关系性的。** 「楠楠说了一句 stay」是 2 还是 8，
取决于楠楠是谁、她这阵子在扛什么。斯坦福能用小模型，是因为他们的记忆对象是玩具世界里的
通用观察（「刷牙」=2、「约暗恋对象」=8），任何模型都判得出。她的不是。

**我们有更好的信号：她自己的书写行为。** `xiaoni-recall-association.js` 的六因子里有四个本来
就是重要性的代理，而且全部来自她亲手留下的痕迹——`effort`（为这条花了多少字）、`prose`
（整段话 vs 日内清单）、`introspection`（有没有写当时卡在哪）、`titleSpecificity`（标题指不指
得出是哪件事）。斯坦福需要 LLM，是因为他们**没有**这个信号；我们有。

由此定下这条分工：

| 层 | 谁做 | 为什么 |
|---|---|---|
| 硬事实（在场排除 / 冷却 / 语料范围） | 代码 | 可验证、可回放；模型没法可靠地知道「这段是不是已经在她上下文里」 |
| 排序（relevance + recency + importance） | 确定性算术 | shadow 日志因此可重算，阈值可校准，回归集才成立 |
| 投递闸的选取与钩子措辞、以及**投多少条**（没有日额兜着） | LLM | 词面/向量够不着的那一层判断；至多 84 拍/天，Haiku 量级下可以忽略 |
| query 展开（标签化 → 组装多 query） | LLM，**自适应触发** | 只在算术拿不出像样候选时才跑；强命中时展开没有价值 |

**这条分工的价值在于回归集**。检索层确定性 ⇒ 历史 shadow 可以重跑对比 ⇒ 权重改一次能立刻
看出变好还是变坏。如果把判断整个交给模型，「阈值调到多少」就变成「rubric 怎么写」，而
rubric 一改历史数据就不可比——这个项目已经吃过一次「样本不够就下结论」的亏
（2026-08-07 只看一天便判定投递节奏没问题，08-13 才发现 24 条全投在她收尾睡觉的时间窗）。

**投递闸的 LLM 请求必须独立发，不要克隆主请求。** 这个栈的 fork 惯例是克隆主请求骑热前缀，
但那意味着每次判断都要过一遍她那几十万 token 的上下文；一个几千 token 的独立请求便宜一个
数量级。这条写下来，否则下一个人会照 fork 惯例「修」回去。

模型可用性（2026-08-19 实测，同一份 OAuth 凭据直连 `api.anthropic.com`）：
`claude-haiku-4-5` 返回 200。栈里此前只调用过 `claude-opus-4-6`，那是「用过什么」，
不是「能用什么」——不要再拿调用记录推可用性。
