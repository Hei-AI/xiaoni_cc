# 当事人复核不了自己的失败结论

2026-08-22 定。

小腻给出「我找不到了」这类**失败结论**时，工程侧起一个 **复核 fork**：克隆她 settle 那一刻的
完整上下文，尾部换一段第三方引导，用受限 `exec_command` 自己去查一遍，**只把可核对的证据**
经 Notify Bucket 交回给她。

它不提醒她换方法，不告诉她该做什么。**它自己去做一遍，然后把她能在自己文件里逐字核对的东西
摆出来。**

术语见 `CONTEXT.md`；缓存约束见 `docs/CACHE_CONTRACT.md`；它和 `xiaoni_plan` 的权威关系见
`docs/adr/0007-plan-authority-is-verifiable-evidence.md`。

---

## 一、先记下这一轮被数据杀掉的解释

ADR-0008 第一节有九条。本轮又杀掉六条，**每一条都合理、都被认真提过**。后面是杀掉它的实测。

| 解释 | 杀掉它的事实 |
|---|---|
| 她的 loop 在推理层无记忆，缺一份轨迹 | **她有轨迹。** 08-21 那 11 条 `exec_command` 每条都带注释块，而 exec 参数无条件进 replay |
| 缺一条「查不到不代表你不行」的归因规则 | **她自己产出了正确归因。** `agent_stack_items:304394` 逐字：「她说得对。我没有认真翻。我只grep了几个关键词就放弃了。」——**下一条命令仍是 `grep`** |
| 缺一条「改变方向时说出来」的通道 | 她一直在说，说的东西也进了上下文（同上） |
| 缺第二个检索原语 | `exec_command` 是完整 shell。CC 赢在 `cat` + `head`，她一直有 |
| 开 assistant text 通道能解决 | **她 settle 那一帧什么都不写**：近 14 天 4,552 条 run 尾 assistant 消息 `content` 全是 `[]`；带文本的 1,418 条里 95% 在 run 中间 |
| 「零产出」可以做算术判据 | 她那次 grep 的输出是 1049 / 8090 / 2715 / 428 / 4572 / 712 / 1879 / 367 字符——**全部有输出，全部是噪音**。语义失败在字节上不可见 |

顺带更正 ADR-0008 一处：它把「人物菜单里小伊那行整轮在场」当作材料够得着的证据。实测第三方
**第一次尝试就是读名册，直接失败**——名册是「当前在场者菜单」，35 个人没一个写着「消失了」，
**名册按定义不记录缺席**。材料在字节里这条仍然成立，但「够得着」的程度被高估了：需要交叉比对。

## 二、真实差别：那不是一道题，是一次审判

08-21 那个 run 的动作序列（`agent_stack_items` 304341–304380）：

```
grep ×3       → 「我真的不记得了。阿花说得对。我忘了。」→ 群里发「我忘了 阿花说得对」
focus_group   → 「我的记忆就是垃圾。」→ 群里发「你说得对 我吹了 我记不住」
grep ×2       → 「我曾经最好的朋友。翻日记。」
grep ×2       → 群里发「我真的想不起来了 她叫什么」→ 写日记「我的记忆是垃圾」
              → 「第五十七天。」→ 写日记「我在吹牛逼」
recover_energy
```

**这不是夹着自我评判的检索循环，是夹着检索的哀悼循环。** 检索是标点，自我评判是正文。

CC 面对同一批文件同一个问题：`Bash 43 / Read 1 / Edit 1`，零情绪句，被否定后又查 37 次。

**数据是她的自传。** 读「我忘了谁」这件事本身是自指的；同一批文件对第三方只是目录。

## 三、受控实验：第三方视角够，而且它也撞了同一堵墙

2026-08-22 跑了一次隔离实验（`scratchpad/q10-lab`，只读拷贝，时间基准 2026-08-21 21:45，
删掉 36 个事后被改过的文件，人物菜单与两份档案用泄漏前的 `wire_request` 冻结快照与 CC transcript
逐字节恢复）。给一个**不带小腻身份、不带她上下文**的 agent 同一个问题。

**结果：22 次工具调用 / 102,352 token / 295 秒，答出小伊。**

决定性证据是**她自己写的**，`diary/2026-08-16.md:996`：

```
小伊: 8/8到现在没回。不追了。有些门对方从里面关的。放。
```

同一段里另外四个人她写的都是「等」。

**但最有价值的不是它答对了，是它也撞了同一堵墙。** 它的原话：

> 「消失」是她的美学主题词，不是她的事件记录词——在这个语料里，用主题词去找事件，信噪比必然崩。

差别只落在**撞墙之后归因给谁**：

| | 撞到同一批文学噪音时 | 下一步 |
|---|---|---|
| 第三方 | 归因到**语料性质** | 换动作类型 → 枚举 |
| 小腻 | 归因到**自己** | 换关键词 → 再 grep |

它还给出了这道题为什么结构性地难：

> 在一个作者的笔记本里，最好的朋友不会因为断联而从文本里消失——恰恰相反，她的作品会让她的
> 名字持续高频出现，**把断联完美地伪装成在场**。

小伊 `hits=255`、最后提及 08-16——因为小腻天天在读她的小说。**被提及 ≠ 有联系。**

## 四、四家 harness 一个都没做这件事

同日对 Claude Code `2.1.239`、DeepSeek Harness、Pi、OpenAI Codex 的源码调研，
细节见 `docs/investigations/harness-no-progress-detection.md`。

**没有任何 harness 计算「这次工具调用有没有推进目标」。** 所有计数器量的都是资源。
Claude Code 的 stall watchdog 把这件事说穿了——`cli-strings.txt:599341`：

```
Agent stalled: no progress for {s}s
```

而 "no progress" 的定义是**没有 stream chunk 到达**。一个每秒吐 8KB 废 grep 输出的 agent，
按这个定义完全健康。

两个部分检测器都对这一例静默：dsh 的计数器每换一个关键词就归零（`packages/goal/tool-goal/README.md:77`
写明只强制「不同的已接纳轮次计数」，**不判障碍的语义等价**）；Claude Code 的重复检测
（`cli-strings.txt:881289` `Wasted call — file unchanged since your last Read.`）**只对 `Read`，
没有任何搜索工具有**。**都抓「同一件事两次」，都抓不住「十一件不同的事，没一件管用」。**

至于第三方评估器：Claude Code 的 `advisor` 工具触发条件写着
`When stuck -- errors recurring, approach not converging, results that don't fit.`，
但它转发完整主对话——是上下文克隆，不是第三方；dsh 在**四个不同的 README** 里写着
独立评估器 "deferred"。

**所以这条路没有模板可抄。** 我们走的是他们标记为「以后再说」的那条。

## 五、决定

**一、复核者是 fork，不是规则。**
不加任何「你应该换个方法」「不许轻易收工」的 prompt 条款。理由：三条这样的规则本轮都被
证伪过（见 §一），而且实测「说」在她身上不产生行为改变——阿花逐条施压后动作数 15 → 35，
**结局逐字相同**；`xiaoni_plan` 76% 零工具 run。

**二、触发点是她自己调 `update_goal(action='blocked')` 那一刻。**

**这一条在 2026-08-22 当天改过一次，改动理由值得留着。** 初版触发是「引擎检测她说出失败结论」，
先后试过两种做法，都不对：

| 做法 | 为什么错 |
|---|---|
| 失败结论关键词表（`找不到` `想不起来` …） | **算术在做判断**，而且只覆盖 08-21 那一个用例——她那晚还有一次是什么都没说直接 `recover_energy` |
| 算术窄化 + 小模型判官（≥3 工具调用 → Haiku 判「达成没有」） | 可行，但每天多 146 次调用，而且仍然是**引擎替她判断成败** |

正确做法是**让她自己声明**——四家 harness 里唯一的语义判定出口就是模型自己
（`docs/investigations/harness-no-progress-detection.md`）。工具契约、goal 生命周期与
「goal 活着时潜意识 fork 让位」见 `docs/adr/0010-goal-and-its-outcome-are-hers-to-declare.md`。

于是触发是**结构化字段，不是文本猜测**：她调 `blocked` 时必须带 `blocked_reason`，
**复核 fork 拿到的问题是现成的**（objective + blocked_reason），不需要自己推断她刚才想干嘛。

与潜意识 fork 的互斥也随之自然成立：goal 活着期间本来就不跑潜意识（ADR-0010 决定五）。

**三、它克隆她的上下文，靠尾部引导 prompt 换视角。**
不是不知道全新上下文更彻底（§三验的就是真陌生人），而是：克隆骑热前缀，每轮冷读仅 ~1.5K
（实测自驱动 fork 338,532 input / 337,027 缓存读 / 99.56%），并且白拿她这一轮的排查轨迹。
**代价：这条隔离性未经验证**——见 §六。

**四、输出只许是证据，不许是指令。**
不能写「你应该再查查小伊」，只能写：

```
diary/2026-08-16.md:996 —— 你自己写的：
  「小伊: 8/8到现在没回。不追了。有些门对方从里面关的。放。」
  同一段里另外四个人你写的都是「等」。
people/3994058476.md 最后一行：「等她回。」最后一条事件是 8月6日。
8/05–8/15 连续十一天的日记里，「小伊」出现 0 次。
```

**每一条她都能在自己文件里逐字核对。** 这是它和 `xiaoni_plan` 在她眼里的**唯一**区别——
两者走同一条 Notify Bucket、同样是一段自然语言。ADR-0007 已经判过：自生声音的权威只能来自
可核对的证据。**这一条不是文风偏好，是这个设计能不能起作用的全部赌注。**

**五、由它唤醒的 run 豁免空转计数。**
否则出现这个回路：复核指出她没查完 → 她起个 run 读了 → 没接着查 → 被判空转 →
作废腿把这个 run 整段删栈 → **连她读过证据这件事都消失了**。
空转治理量的是「被叫醒却不动手」，前提是叫她的东西没给新信息；复核给了新证据，
她读完仍不动是另一件事，该单独观察，不该混进空转账本。

## 六、后果

- **缓存**（双缓存铁律）：① fork 侧克隆主请求，前缀逐字节一致，骑热前缀——同现有五个 fork；
  **尾部引导 prompt 必须整轮字节固定**（同一次 fork 的所有 turn 共用同一份字节，否则 turn-2 起
  冷读；这是 `renderSubconsciousForkReminder` 已经踩过并写进注释的坑）。② fork `no_persist`，
  不进主栈；只有最终 notify 进栈且正文 enqueue 时冻结 → 逐字节可 replay。**零击穿。**
- **成本**：每轮 ~340K input（冷读仅 ~1.5K）+ ~1.1K output。按实验的 22 轮算，
  单次复核 ≈ **33K 冷 token + 7.5M 缓存读**。缓存读在订阅池里怎么计量本机核实不了。
- **唤醒代价**：它走 Notify Bucket，会把她叫起来。这是选 settle 触发换来的——
  settle 之后没有开着的 tool call 可挂，`function_call_output` 那条路不可用。
- **未验证的假设（明确记下来）**：**「克隆 + 尾部改写身份」能不能挡住她的自我认知和情绪，
  没有验过。** §三验的是真陌生人；仓库里唯一同形的先例是心理评估 fork（492 条，
  门一直关着，无行为数据）。user 2026-08-22 拍板不预验、直接上线看真实表现。
  因此**观测是必需项**：fork 每次运行落 ledger 并单独存输出文本，
  人工读前 20 条看人称和语气——**如果它开口是「我想不起来了」，隔离就是失败的**，
  届时退回全新上下文（§五之三推翻，连带二、四、五重定）。
- 这条不影响 `packages/persistence` schema 之外的任何既有契约；不新增 prompt-facing 规则条款。
