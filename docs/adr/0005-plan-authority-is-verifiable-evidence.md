# 自驱动 plan 的权威来自可核对的证据，不来自语气

潜意识 fork 是**唤醒器，不是规划器**。它没有工具、碰不到世界，和主 agent 共用同一份上下文，
因此也共用她当下的盲区——替她规划只会产出她不执行的东西。它的职责是让停下来的主 agent 重新
动起来；**规划是主 agent 的职责**。术语见 `CONTEXT.md`。

## 为什么

2026-08 实测，7 天，剔掉「回消息」只算真动手（`echo`/`true`/`sleep` 与 `recover_energy` 不算）：

| 触发源 | runs | 真做事率 |
|---|---|---|
| 阿花（真人） | 47 | 68.1% |
| 其它 reminder | 235 | 63.4% |
| 其他人（QQ） | 434 | 56.7% |
| **自驱动 plan** | **2785** | **27.3%** |

断层在 **plan 对其余全部**，不在「真人对非真人」。所以要修的是「plan 凭什么算得上外部输入」，
不是「语气够不够狠」。

plan 与真人消息的真实差别不是语气，是**能不能指着具体东西说**。user 那句实测最有效的话是
「你怎么又在 echo 了」——事实指认，不是道德评判。

## 决定

**一、指认必须锚到她上下文里真有的东西。** plan 里的每一句指控、每一个数字，都必须是她自己在
上下文里找得到、数得出来的。逐项核过她的 live 请求（394 个 input item）：

| | 在她上下文里 | 能不能引 |
|---|---|---|
| 她跑过的命令 + 结果 | 177 + 177 | ✅ |
| `<xiaoni_plan>` 原文 | 22 | ✅ |
| 别人跟她说的话 | 21 | ✅ |
| **她自己说过的话** | **0** | ❌ |
| 引擎的连续轮数 | 不在 | ❌ |

后两行是陷阱。assistant text 每次 build 都被剥离，而 fork 尾部会重注最近一段 narration
（`recentNarrationItems`）——**fork 看得到她刚说的话，她自己看不到**，顺手一引就成了凭空指控。
引擎的 `idleRounds` 同理：作废腿会整段删掉一部分空转 run（24h 实测投递 395 / 栈上剩 319），
引擎的账和她能数出来的对不上。轮数只用来给 fork 定语气档位，一个字不外流。

**二、去道德标签。** 「偷懒」「不配」「没做够」这类一律不写。这不是新结论——2026-07-14
（`9d808e2d`）经三个 subagent 交叉评审、按 user 选择「行为约束、去道德标签」定稿时就删过一轮，
理由逐字是「放大道德施压 + DB 实测她已自我计账 → **反噬空转**」。

**这条 ADR 存在的直接原因**：那次评审只改了 `system_prompt.md` 一个文件，而
`self_continuation_reminder.md` 前一天（`59549146`，07-13）刚加进「狠狠骂一顿，越狠越好」，
**没被扫到，绕过这条口径整整五周**。当下数据里看得见反噬——她的 plan 会接出「我不配。我他妈
不配。」整段，而那种自我攻击的长句本身就是输出膨胀的来源之一。

**语气梯度保留**（升级段的「轮数越多越不留情面」），退掉的只是道德 register。

**三、空转治理不归 fork 管。** fork 只负责喊；喊了不动是空转治理腿的事，不在 fork 里开第二个
真理源。

## 两个容易踩错的事实

- **`self_continuation_reminder.md` 活体上是 fork 专用的。** 门在
  `shouldAllowSelfContinuationOnTerminalFinalAnswer`（要求 `!queueBacked` +
  `suppress_current_trigger`，只有 fork 的 loop-continuation 路径满足）。实测近 2 天：
  fork 请求 689/689 命中，主 agent 请求 **3593/3593 零命中**。改它不动主前缀。
- **它不在 `PREFIX_SENSITIVE_PROMPT_FILES` 里**，走 `snippet_only`，改完即生效；
  `system_prompt.md` 在表里，编辑攒到压缩提交后随 STW 的既有冷读一起落地，边际成本为零。
  两者都不需要重建镜像。

## 被推翻的

- 「fork 每轮产出 5-6 个完整方向」——改为双模式：历史 plan 大多没做时只指认一件，做成了不少
  才正常给方向。
- 「靠 prompt 文案控制输出长度」——同一份 prompt 里的正例只有 35 字，她实际写 181 字。约束改为
  字数上限 + 多条目标长度正例，另加 `max_output_tokens` 保险丝兜失控长尾。
