# 小腻自维护的记忆文件归她所有，工程侧只读

`notes/diary/open-loops.md` 与 `notes/xiaoni-identity-anchor.md` 是小腻自己写、自己重写的文件，
不是工程可以修补的数据结构。两条实测事实划出这条边界：

- `open-loops.md` 是**快照，不是账本**：压缩写入清一色 `cat > file << EOF`，零 `>>`；
  2026-07-27 有铁证——读回 13 行后同一分钟写回，丢掉 3 条仍 open 的行。
  任何「依赖某内容在该文件里存活 N 轮」的设计都不成立。
- `xiaoni-identity-anchor.md` 是**活文件**：现 25.7KB，mtime 由压缩帧持续更新（文件头自称的
  最后更新日期是过期的），内部已含按天条目、人物档案、反思沉淀。
  在别处另起反思或人物 sink 会造成双 sink。

因此工程侧的正确动作是**给她原子操作**——一个她能调的 skill 或工具，让格式由工程收口。
只读索引可以，改她写的内容不行。见 ADR-0003（同一条原则在产物写入器上的形态）。
