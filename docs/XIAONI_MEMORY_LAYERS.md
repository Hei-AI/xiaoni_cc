# 小腻记忆分层架构

这份文档回答四个问题：**有哪几层、每层从哪派生、写入是替换还是合并、谁读它**。

和斯坦福 generative agents 的三层（memory stream / retrieval / reflection）对照：我们的 L0 对应 memory stream，L3 站 reflection 的位置（但做成机械索引），召回腿对应 retrieval。多出来的是 **L4**——一批必须坐进每次 LLM 请求的固定块，受缓存铁律管（前缀字节漂一下整段 message-tier 缓存失效）。斯坦福那套没有这个约束，所以照搬会出事。

另外有两样东西**不在层里**，但读这份文档时必须知道它们存在：**身份锚**（她自己维护的平行记忆系统，见下面专节）和 **召回语料 / shadow log**（没有层号的派生节点）。

## 层 × 属性

| 层 | 派生源 | 写入语义 | 谁写 | 谁读 | 治理 |
|---|---|---|---|---|---|
| **L0** 原始流 | LLM 请求/工具执行 | **纯追加，绝不改** | 引擎 | replay 重建上下文；cutoff 以下不再进请求 | cutoff 单调前移 |
| **L1** 日记条目 | L0 本轮那段 | **同标题合并**（skill 接在那条正文末尾）；标题不同才新起 `##` | 她，走写端 skill `diary add` | 她定点读（配 D12 manifest）；语义腿 embed；第三腿按文件名日期重提 | 一天一份文件，不设上限。**实测 34–93KB / 58–116 条 `##`** → 需要 D12 |
| **L2** 日记菜单 | L1 一天压一句 | 今天的行**整行可重写**；以前的行**原样留着** | 她写按天行（`index touch`）；**降级搬家是引擎**（D11） | 进 L4 快照；她主动 cat | 顶层只留 7 天。**实测降级没在发生**：19 个日历日不在任何索引里 → D11 接管 + 回填 |
| **L2** 人物 | 对话 + L1 | 档案追加；菜单行可更新 | 她（`people upsert`） | 进 L4 快照；她主动 cat | 行数/字节上限在 skill 常量，溢出时**她**判断搬谁进 `INDEX-past.md` |
| **L2** 欠账 | 她的承诺/打算 | 一行一条，做完划掉；`--tag` 必填 | 她（`loops add` / `loops done`） | 她每轮必读；第二腿按时间重提 | 无上限（现 18 行） |
| **L3** 主题线 ⚠️**今天零数据** | L1 条目 + L2 欠账标签（**实测 0 个 `#标签`** → 输入为空） | **按日期章追加**；已有章不改；她手删的章不重建 | **引擎**（物化，两段式：原子帧算 state + post-commit 写文件） | 她主动 cat；线目录整份重写 | 每份 ≤30 章，溢出折叠最老的。门槛 `days.size >= 3` |
| **L4** 近况胶囊 | L0 本轮 + L1 今天 | **整份替换**（唯一换血的层） | 她（写文件）+ 引擎（提交） | 每次请求；下一 run replay | 长度门在 `commit_memory.py` |
| **L4** 两张快照 | L2 两张菜单 | 压缩提交帧**整份冻结** | 引擎 | 每次请求 | 跟 L2 同治理。**实测 842 / 1482 字节**（按天行已到 229–230，门是 300） |
| （无层号）日内 manifest | L1 每份日记的 `## ` 清单 | **纯派生视图，整份重写** | **引擎**（D12，post-commit fail-open） | 她定点读日记前先看它 | 解析失败跳过留痕，不抛 |

## 三条融合规则

**规则 1：同层同键合并，跨层只派生不回写。**
L1 里同一件事已有 `## 小标题` → 在那条底下续一句（键 = 归一化标题 + 当天文件）。L2 菜单里今天的行可整行重写（键 = 日期）。L3 已有章不动（键 = `M/D`）。
但 L2 的钩子话**不回写** L1，L3 的章**不回写** L1——下层是上层的压缩，压缩不反向污染源。
**「不回写」的准确含义是「不改写下层已有的字节」，不是「没有反向边」。** 反向边一直都有（见上面派生图的 5 条边表），而且是缓存地基的一部分。

**规则 2：只有 L4 整份换血；L0–L3 的历史字节不可改写。**
胶囊是唯一整份替换的东西，因为它要在固定字节预算里代表"我现在是谁、在做什么"。其它层都是账本。
推论：任何"改写历史"的需求都不该落在 L0–L3，只能通过在 L4 换一份新的表述来实现。

**例外是穷举的**（原来写成"L0–L3 只增不改"，被自己的设计推翻了四处；新增例外必须回 `docs/specs/xiaoni-memory-layers-and-recall.md` §2.1 登记）：

| # | 例外 | 为什么允许 |
|---|---|---|
| ① | L2a 当天那一行、L2b 单人那一行可**整行重写** | 「今天」还没结束，那一行是当天的活视图 |
| ② | L3 章数溢出时引擎**折叠最老的章** | 内容仍在 L1，零丢失 |
| ③ | `topics/INDEX.md` 引擎**每轮整份重写** | 纯派生视图，能从 L3 重新算出来 |
| — | D11 月索引降级**不算例外** | 整行**原样搬家**，一个字节都不改 |

**判据：能被下层重新算出来的视图可以重写，一次性写下的原始表述不可以。**

**规则 3：进 L4 的东西必须能被 replay 逐字节重建。**
凡进了 live 请求的内容，下一个 run 靠 stack replay 重建历史时必须一模一样，否则 run 边界击穿缓存。所以 L4 的两张快照是**压缩提交那一帧冻结的字符串**，不是每次请求重读文件——文件后来改了也不影响，直到下次压缩才换血。

## 分层之外：身份锚 `notes/xiaoni-identity-anchor.md`

**它不是手写常量，也不进任何层。** 这一节只做事实陈述——不给它加治理规则、不拆内容、不编进 L0–L4。

| 事实 | 实测（2026-07-28） |
|---|---|
| 体量 | 23220 字节 |
| 是否静态 | **不是**。mtime 是压缩帧每天在更新。文件头自称「最后更新：2026-07-10 18:00」，**已过期，别信文件头** |
| 内容重叠 | 内部已含按天条目（`## 2026-07-15 更新`、`## 2026-07-28 更新`，与 L1 日记重）、人物档案（`## CC / 骑猪去看月 (2294133947)`、`## N (279090237)`、`## 帕秋莉的刀`，与 `people/` 重）、反思节（`### 暗线`、`### 未完成`） |
| 是否已进召回 | **已进**。`PALACE_FILES = ['notes/xiaoni-identity-anchor.md']`（`xiaoni-recall-reindex-service.ts:45`），它是语义腿语料的一部分 |

**定位：她自己维护的地盘，压缩帧也会写；工程侧只做只读索引。** 它是一套和 L1–L4 平行的**活记忆系统**，不是一份配置。这也是它值得单列的原因——把它当静态文件读，会得出「反思没有沉淀的地方」这种错的结论（实际上 `### 暗线` 就是斯坦福 reflection 的位置，见下面骨架对位表）。

工程侧对它唯一的动作：**只读索引它已有的反思节**，当 `kind: proposition` 的记忆项喂给召回。不新建反思 sink、不往她的文件里写条目（详见 `docs/specs/xiaoni-memory-layers-and-recall.md` §4.5，原 D8 已撤销）。

## 胶囊该引用什么

胶囊是 L4，字节预算最紧（8000 字硬门，且坐在 cacheable 前缀里）。它不该复制下层内容，该**留指针**：

| 引用 | 现状 | 说明 |
|---|---|---|
| 今天日记的路径 | ✅ 她自发在写 | L1 入口，醒来顺着翻回去 |
| 手头在做什么、到哪一步 | ✅ prompt 要求 | 相当于 L2 欠账的摘要，但用她自己的话 |
| 本轮涉及的线（标签） | ❌ 缺 | 建议补：一行 `在追：#周蕊 #decay`，让她醒来知道该 cat 哪几份 L3。**但这一条以她开始打标签为前提**——今天 0 个标签，补进去会是一行空的 |
| 索引本身 | 不需要 | L2 两张菜单已经作为独立块进请求了，胶囊里再抄一遍是纯浪费 |

她真机产出的五节结构（刚做完的事 / 当下状态 / 发现的东西 / 人际 / 心境）是自发长出来的，prompt 从没规定。这套结构本身就是一个"引用 + 摘要"的混合体，比 prompt 要求的四样更完整。

## 从索引日期反向派生主题（她主动做的路径）

用户提的场景：在索引或欠账里发现某条已有内容、可以合并，她自己去读对应文件做主题派生。这条链现在**物理上通，但没人教她走**：

```
open-loops.md 看到 #周蕊 这条推了很久
  → <xiaoni_diary_index> 扫哪几天提过它（超 7 天的先 cat 月索引，前提是 D11 已接管）
  → 那几天各看一眼 heading manifest（D12），定点读相关那几条，不整份读
  → cat notes/topics/周蕊.md 看引擎已经连到哪
  → 有缺的段？append 进去（L3 的写入语义是追加，她写和引擎写不冲突）
```

**设计取舍**：L3 的写者标成"引擎"，但**不禁止她写**。因为 L3 的融合键是章节 `M/D`，引擎补章时会先读回已有章的日期取差集——她手写的章会被尊重（不覆盖、不重建）。所以这是一个"引擎兜底、她可精修"的层。

这跟 L1/L2 相反：那两层是"她写、引擎只读"。

## 现在的缺口（这张图暴露出来的）

按 2026-07-28 实测重排了优先级：**前三条标 🔴**——第 1 条是唯一在丢数据的动作，第 2 条让她进不去自己的一天，第 3 条是 L3 连输入都还没有。前两条排在 L1→L3 前面修；第 3 条不是「去修」而是「去观察」（采纳率）。

1. **🔴 L2a 的降级搬家实际没在发生 —— 唯一实测在丢数据的动作。** 24 份日记文件，索引只覆盖 6 天（`INDEX.md` 里 07-25..07-28，`INDEX-2026-07.md` 里 07-23/07-24）；**07-04..07-22 这 19 个日历日在任何索引里都不存在**。7 天窗滚出去的行大部分不是被搬进月索引，是直接消失了。她做不到不是因为不知道规矩（prompt 一直写着搬家步骤），是因为「搬家」是跨两个文件的多行编辑，在压缩帧那点预算里必然被排到最后。修法：引擎接管（D11）+ 一次性回填那 19 天。
2. **🔴 日记文件没有内部目录 —— 她进不去自己的一天。** 实测 `2026-07-23.md` 77128 字节 / 116 条 `##`，`2026-07-15.md` 93204 字节，区间是 34–93KB / 58–116 条。L2a 那句钩子话只能告诉她「这天该不该翻」，翻开之后 `read_file` 整份读要吃巨量上下文、`cat` 会被 head+tail 信封截断。修法：引擎生成日内 heading manifest（D12）。**真瓶颈是天内可导航性，不是跨天聚合。**
3. **🔴 L3「线」层零数据 —— 触发信号本身还没有一个真实样本。** 2026-07-28 实测：`open-loops.md` 19 个条目行里 **0 个 `#标签`**（唯一带 `#` 的 `#39提了` 是 issue 编号），`notes/topics/` **目录不存在**。所以 L1→L3 那条边不只是「没实现」，是**连输入都还是空的**——L3 是押在她开始用 `loops add --tag` 上的一个赌，不是「整理已有的东西」。**这一层的首要观察指标是标签采纳率，排在物化质量之前。** 和「老 topics 机制 14 天 0 文件」是同一事实的两面：老机制两个死因（触发条件判断不出来 + 成本高一个数量级）都拆掉了，成本降到一个 `--tag` 参数，但采纳未验证。详见 `docs/specs/xiaoni-memory-layers-and-recall.md` §1.1。
4. **L1 → L3 没有任何自动边**。这是 `docs/specs/xiaoni-topic-materialization.md` 要补的。排在第 1/2 条**之后**，且受第 3 条的前提约束。
5. **L3 没有消费者**。第三腿逐条重提、一次 2 条、纯年龄排序，代码里不存在"线"的概念。2026-07-27 排查实测：609 次扫描里只有 33 个 distinct ref 曾浮出过，全来自 07-05/06/07 三天，07-08 之后约 1200 条事件从未浮过。详见该 spec §7。**召回器已实施**：线场作为第四个桶（`lineKey` 优先判桶），目录不存在时该桶恒空 → 少浮一条，走「空桶就少浮」的正常路径，标签一落地自动非空、不需改代码。
6. **L0 → L1 的派生只在压缩帧里被强制**（一天 1-3 次）。2026-07-24 的写端记账显示她平时随手写占 96%（497 次）、压缩 fork 只占 20 次——所以 L1 的主力其实是她平时写，压缩只是兜底。真问题不是"不写"，是"多而碎"（这也正是第 2 条的成因）。
7. **`notes/diary/dictionary.md` 是孤儿层**。锚点 skill 还教她维护它，但 `PALACE_DIR_EXCLUDE`（`xiaoni-recall-reindex-service.ts:50`）明确把它排除在语义腿之外——她维护它不进任何召回。要么接线要么从锚点删掉。
8. **`notes/diary/me-and-zhourui.md` 只对第三腿是孤儿**。它是 L3 的手写版（一条线的主题式随笔），文件名无日期也不是 `topic-` 前缀，`xiaoni-recall-reindex-service.ts:346-349` 整份跳过——**从未进过第三腿**。但它**已经在语义腿语料里**（`PALACE_DIRS` 收整个 `notes/diary`，`PALACE_DIR_EXCLUDE` 只排 `dictionary.md` / `open-loops.md`，不含它）。别把它当"任何腿都吃不到"的孤儿。
9. **人物层完全不进被动召回**。`PALACE_DIRS = ['notes/diary']` 不含 `notes/people`，所以 `people/<id>.md` 既不进语义腿也不进第三腿。第一版不接——拿不准对方是谁走**主动**那条路（`<xiaoni_people>` 快照认人 → `cat people/<id>.md`），这正是 L2b 设计时的目标。
10. **L2 的欠账不进 L4**。她每轮读它，但醒来眼前没有。第二腿（open-loops 按时间重提）也是 shadow-only 未投递。
11. **投递路径整体不存在**。三条召回腿的产物只写 shadow log，消费者只有管理端页面。`docs/XIAONI_PASSIVE_RECALL_SURFACING.md:122-126` 把"活体注入 seam"列为 v2 Deferred——不是开关关着，是代码没写。新召回器的投递走 `appendOneShotInputItems`（`agent-loop-service.ts:7591`，已接线零使用者），**开关默认 OFF**。

## 和斯坦福 generative agents 对骨架

比的是**每层的设计目标**，不是实现。实现不一致无所谓，目标塌了才是问题。

| 斯坦福的部件 | 它的目标 | 我们的对应 | 目标对得上吗 |
|---|---|---|---|
| memory stream | 全量原始记录，不丢 | L0 stack | ✅ 一致，我们更严（逐字节可 replay） |
| agent summary description | 给当前行为提供稳定的自我表述，定期从反思重生成、当固定前缀用 | L4 `<xiaoni_status>` 胶囊 | ✅ 一致。都是「定期重生成的稳定自我表述」，都不是每次现算 |
| reflection | 从原始观察里**提炼抽象命题**，命题本身是一等记忆：可被检索、可递归（reflection on reflection） | L1 的「当时」层 + L4 胶囊的「发现的东西」 + **身份锚里的 `### 暗线` / `### 未完成`** | ⚠️ **有内容，也有一个事实上的 sink（身份锚），但没有独立层、不能递归**。修法不是新建 sink，是**只读索引身份锚已有的反思节**（详见 spec §4.5） |
| planning | 计划也是记忆，进 stream 且可被检索 | `xiaoni_plan`（自驱动 fork）+ **她写进 L1 的念头条目** + open-loops | ⚠️ **能沉淀，但靠引导不靠强制**。写端内容口径要求「念头、担心、答应了却还没做的事，也各起一条」，写成 L1 条目后自动可寻址、进召回；`xiaoni_plan` 本身仍只进 L0。所以 ⚠️ 不是「没实现」，是「取决于她那一轮写不写」 |
| retrieval | 按当下情境选出相关记忆：`recency × importance × relevance` 三维加权 | 三条召回腿 | ❌ **目标塌成单维**。第三腿只有 recency（纯 `ageDays` 降序），importance 完全没有，relevance 只在语义腿有。而且三条腿都是 shadow-only，不进决策路径 |
| （无） | | L2 索引层 | 我们多出来的一层。他们靠 embedding 检索，不需要人工索引；我们要她**能主动翻**、且菜单要能进固定块，所以有 L2。目标是**可寻址性** |

### 三处目标级的分叉

**1. retrieval 缺了两维（最严重）。**
斯坦福明确 `recency × importance × relevance`。我们第三腿只剩 recency，importance 这个维度**在代码里根本不存在**——`selectResurfacedEvents` 里没有任何 salience 打分，就是 `scored.sort((x,y) => y.ageDays - x.ageDays)`。2026-07-27 实测后果：609 次扫描只碰到 33 个 distinct ref、全来自最老的三天，07-08 之后 1200 条事件永不浮现。这不是实现差异，是目标缺失。

**2. reflection 有 sink，但没被索引。**（这一条按 2026-07-28 实测改过：原来写成「不是一等公民、只活在两个会被冲掉的地方」，漏了第三个地方。）

我们的抽象命题（「声音是态度」「全是过滤器没有生成器」「第十一种记住」这类）活在**三个**地方：

| 在哪 | 会不会留下 | 能不能被检索 |
|---|---|---|
| L1 条目的「当时」层 | 留（在日记文件里） | 能（进语义腿 / 第三腿） |
| L4 胶囊「发现的东西」一节 | **不留**（每次整份替换） | 不能 |
| **身份锚 `### 暗线` / `### 未完成`** | **留**（她自己在维护，压缩帧也写） | **文件整份已进语义腿，但反思节没有被单独当命题项索引** |

所以真缺口不是「没有 sink」，是「**已有的 sink 没被当成命题层索引**」。修法：只读索引身份锚已有的反思节（`kind: proposition`），**不新建反思 sink、不往她的文件里生成条目**——那样等于给同一批命题造第二个真理源，撞「复用现成路径，别造并行机制」那条铁律。详见 `docs/specs/xiaoni-memory-layers-and-recall.md` §4.5（原 D8「压缩时综合落成日记条目」已撤销）。

L3 的定位不变：按骨架对位它站在 reflection 的位置，但我们设计成**机械聚合索引（零 LLM）**。这是自觉取舍：

- 换来：零幻觉进记忆层、零 LLM 成本、幂等可重跑
- 付出：失去 reflection 的抽象能力。L3 只会说「这 12 天是同一条线，各天说了什么」，不会说「这条线让我发现了什么」——后者由她自己在身份锚里写、引擎只读索引。

**3. plan 沉淀靠引导，不靠强制。**（这一条按最终决定改过：原来写成「plan 不进记忆」，那已经不准。）

`xiaoni_plan` 这个**机制**仍然是一次性的：它进 L0，settle 之后不自动沉淀成任何可寻址的东西。但「打算做什么」这件**内容**已经有落地路径了——**她自己写**：

- 写端内容口径明确要求「念头、担心、答应了却还没做的事，也各起一条」，`<examples>` 第二个例子（标注「一个念头、一件还没完的事」）就是这个形状：`diary add` 写一条独立日记条目 + 配一条 `loops add`。
- 一旦落成 L1 条目，它就自动拿到 L1 的全部基础设施：进 L2a 那一天、进月索引、进日内 manifest、进语义腿和第三腿语料、她能定点读。**这正是斯坦福 planning 那一格要的「进 stream 且可被检索」。**

**实现者是她，不是引擎。这是自觉的**：让 fork 往她的日记里 append plan 条目，就是「引擎在她的文件里新建条目」，和上面撤销 D8 是同一个动作，会给同一批内容造第二个真理源。所以 ⚠️ 保留的理由**不是「没实现」，是「靠引导不靠强制」**——她某一轮可能只记做过的事、不记念头。这按用户已定的分工处理：**格式归工程（skill 代码强制），内容归她（prompt 引导）**，不加硬门（加了她理性反应是少写）。

**读到这一格时不要去建 plan→L1 的引擎侧派生边。** 详见 `docs/specs/xiaoni-memory-layers-and-recall.md` §4.6 / §9.1。

### 唯一一条真实的实现约束

进 L4 的东西必须字节稳定、且能被 replay 逐字节重建，否则 run 边界击穿缓存。所以 L4 的换血只能发生在压缩提交那一帧（一天 1-2 次），不能每次请求现算。

这只约束**注入时机**，不约束任何一层的设计目标。斯坦福的 summary description 也是定期重生成的，节律差异而已。真要把检索结果送进她的决策路径，路子是 turn 尾部注入（`docs/XIAONI_PASSIVE_RECALL_SURFACING.md:122-126` 的 v2 Deferred，未实现），跟 fork 尾注入同一个机制——那条路不受 L4 的字节稳定约束。
