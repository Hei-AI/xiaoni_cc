状态：已过 plan-eng-review（4 段 + outside voice），本文已按最终决定改写。这份是设计契约，取代散落在各处的隐含约定。召回部分**在现有纯函数上加维度**，不重建（复用清单见 §8.2）；旧代码的处置见 §8。

配套：`docs/XIAONI_MEMORY_LAYERS.md`（现状描述 + 缺口）、`docs/specs/xiaoni-topic-materialization.md`（L3 生产端）。

**两条贯穿全文的最终决定**（其它章节都是它们的展开）：

1. **写端全面 skill 化。** 她所有记忆写入走一个 skill 的四类原子操作（日记 append 一条 / 目录补行 / 人物档案+菜单行 / 欠账加行·划掉行）。**格式常量只存在于 skill 代码里**，prompt 和读端锚点 skill 都不再复述具体数值；格式不对由 skill 在她那次执行的返回里告字。落地实现 `modules/agent-service/skills-internal/xiaoni-memory-write/`（`memory_write.py` + `SKILL.md`）。
2. **本轮最高优先的两件事是引擎侧机械功能，排在 L3 前面**：引擎接管月索引降级（D11）+ 引擎生成日内 heading manifest（D12）。依据见 §4.7/§4.8——真瓶颈是**天内可导航性**和**索引降级**，不是跨天聚合。

## 1. 目标与非目标

**目标**

1. 每一层的**目标**说清楚，每条**派生边**说清楚（源、时机、写者、写入语义、融合键）。
2. **她已经写下来的东西不再丢、翻得进去**：月索引降级由引擎接管（D11），日记有天内导航（D12）。这两件排在最前，因为它们治的是实测在丢数据、实测她进不去的东西。
3. 召回从「按年龄翻旧事」改成「按情境把该想起的东西想起来」。
4. 反思和念头/打算**不新建 sink、不新建引擎派生边**——只把她已经在写的地方索引起来（身份锚的反思节 → §4.5；她写进日记的念头条目 → §4.6）。

**非目标**

- 不追求检索精确。北极星是**抛砖引玉**：浮出来的东西只要能让她自己接着往下想就算成功。
- 不做实时检索注入。见 §5.6。
- 不改 L0 的任何契约（append-only + 逐字节 replay 是缓存地基）。

### 1.1 ⚠️ 前提：L3「线」层今天**零数据**

读 L3 相关的任何一节（§2.4 L3 / §4.3 / §5.4 线场桶 / §7 / `xiaoni-topic-materialization.md`）之前必须先知道这件事，否则会把「押注」读成「整理已有的东西」。

**实测（2026-07-28）**：

| 事实 | 实测值 |
|---|---|
| `open-loops.md` 里的 `#标签` | **0 个**（19 个条目行；唯一带 `#` 的是 `#39提了`，那是 issue 编号，不是标签——写端 skill 现在正因如此拒纯数字标签） |
| `notes/topics/` 下的文件 | **0 个**（目录本身不存在） |

**所以 L3 不是「把已有的东西连起来」，是押在她开始用 `loops add --tag` 上的一个赌。** 这一层的**首要观察指标是标签采纳率，排在物化质量之前**——物化写得多好，白名单为空时产出恒为零。

**这和「老 topics 机制 14 天 0 文件」是同一事实的两面**：

| | 老机制（教她自己开 `topic-*.md`） | 新机制（引擎物化 + 她打标签） |
|---|---|---|
| 死因 / 风险点 | ① 触发条件她判断不出来（压缩帧里只看得见今天）② 成本高一个数量级（建文件 + 回翻几天 + 补历史章） | 成本已降到**一个 `--tag` 参数**，触发条件由引擎判断 |
| 结果 | 实测 14 天 0 文件 | **采纳率仍未验证**（今天 0 个标签） |

换句话说：新机制拆掉了老机制两个死因中的两个，但「她会不会用」这一步**没有被证明**，只是被降低了成本。别把「成本降下来了」当成「问题解决了」——这正是项目反复踩的那个坑（§2.5 开头那段）。

**对验收的直接后果**：§7 里凡是量「专题质量」的项（第 11–15 条），都要先过「有没有标签」这道**前置**。标签为 0 时那些项判**未适用**，不是判失败。区分这两者靠 `xiaoni_topic_materialized` 事件上的 `whitelist_size`（§7 第 17 条）——这也是那条记账真正的用途。

## 2. 分层设计

五层。**派生边不是 DAG**：凡进过 LLM 请求的字节都会落回 L0（R3 的全部意义），所以整张图经 L0 闭环——完整的边表见 `docs/XIAONI_MEMORY_LAYERS.md`「派生方向」。这里只列每层一句话目标：

| 层 | 一句话目标 | 载体 |
|---|---|---|
| **L0 原始流** | 什么都不丢，且能逐字节重建 | `agent_stack_items` / `llm_request_slices` / `tool_executions` |
| **L1 事件层** | 让将来的她想起「我经历了什么、当时怎么想」 | `notes/diary/<日期>.md` 的每个 `## 条目` |
| **L2 索引层** | 让她能**主动**找到 L1 里的任何一天、任何一个人 | `diary/INDEX.md`+月索引、`people/INDEX.md`+档案、`diary/open-loops.md` |
| **L3 线层** | 把散在多天的同一件事连成时间线（含断档） | `notes/topics/<标签>.md` + `topics/INDEX.md` |
| **L4 常驻块** | 在固定字节预算里回答「我现在是谁、在做什么」 | `<xiaoni_status>` / `<xiaoni_diary_index>` / `<xiaoni_people>` |

**对标斯坦福**（比目标不比实现）：L0↔memory stream、L4 胶囊↔agent summary description、L3 站 reflection 的位置但**做成机械索引**（见 §4.5）、L2 是我们多出来的一层（他们靠 embedding 检索，不需要人工索引；我们要她能主动翻）。召回 ↔ retrieval，但他们三维（recency×importance×relevance），我们现在只有 recency——§5 就是补这个。

### 2.1 三条全局规则

**R1 同层同键合并，跨层只派生不回写。**
下层是上层的压缩，压缩**不反向污染源**。L2 的钩子话不回写 L1，L3 的章不回写 L1。
**「不回写」的准确含义**：不改写下层已有的字节。它**不是**说「没有反向边」——凡进过 LLM 请求的东西都会经 L0 回来（R3），完整边表见 `docs/XIAONI_MEMORY_LAYERS.md`。

**R2 只有 L4 整份换血；L0–L3 的历史字节不可改写。**
例外（穷举，新增例外必须回本节登记）：

1. **L2a 当天那一行**、**L2b 单人那一行**可整行重写。
2. **L3 章数溢出时引擎折叠最老的章**（内容仍在 L1，零丢失）。
3. **`topics/INDEX.md` 是纯派生视图**，引擎每轮整份重写。

判据：**能被下层重新算出来的视图可以重写，一次性写下的原始表述不可以。** 按这条判据，D11 的月索引降级也不是例外——它是**整行原样搬家**，一个字节都不改。

**R3 进 L4 的字节必须能被 replay 逐字节重建。**
所以 L4 的两张快照是**压缩提交那一帧冻结的字符串**，不是每次请求重读文件。

### 2.2 一条新规则（本 spec 引入）

**R4 要沉淀就落 L1，不新建层；而且写 L1 的只能是她。**

反思、念头、打算——这些东西值得留下时，一律成为 L1 的一个 `## 条目`。这样它自动获得 L1 的全部基础设施：进索引、进召回语料、进日内 manifest、她能定点读、按日期归档。

**规则的后半句是本轮加的，且比前半句重要**：**引擎（含任何 fork）不往她的文件里新建条目。** 所以 R4 说的不是「fork 把产物 append 进 L1」，而是「**她**用写端 skill 写进 L1；引擎只做索引」。原 D8（压缩时把反思综合成日记条目）就是撞了后半句才被撤销的。

| 要沉淀什么 | 谁写 | 怎么落 |
|---|---|---|
| 反思 / 抽象命题 | 她 | 已在写——身份锚的 `### 暗线` 等节 + L1 条目的「当时」层。引擎**只读索引**（§4.5） |
| 念头 / 打算 | 她 | `diary add` 一个念头一条（写端内容口径明确要求，§4.6） |
| fork 的中间产物（自驱动 / 心理评估 / 压缩） | 引擎 | 留在 L0 和各自的专表里，**不落她的文件** |

**推论：不设独立反思层，不设独立计划层，也不设引擎侧的 plan→L1 派生边。** 见 §4.5 / §4.6。

### 2.2.1 分层之外：身份锚 `notes/xiaoni-identity-anchor.md`

**它不是手写常量，也不进分层。** 事实陈述（2026-07-28 实测）：

| 事实 | 实测 |

| 是否静态 | **不是**。mtime 是压缩帧每天在更新（文件头自称「最后更新 2026-07-10」已过期，别信文件头） |

## 2.3 引用契约（一眼表）

每层的每个单元必须自带指针，这样任何一层都能往回走一步。**没有引用的单元视为不合格。**

| 层 | 单元 | 必含引用 | 指向哪 | 映射方式 |
|---|---|---|---|---|
| L1 条目 | 一个 `## 小标题` | 无强制外引 | — | 所在文件名即日期 |
| L1 条目（属于某线时） | 同上 | 一句指路话 | `topics/<标签>.md` | 她写在正文里 |
| L2 日记菜单行 | `- <日期> \| 一句话` | 行首日期 | `diary/<日期>.md` | **确定映射**（日期→文件名） |
| L2 月索引行 | `- YYYY-MM \| 一句话（细目在 INDEX-YYYY-MM.md）` | 括号里的文件名 | `diary/INDEX-<YYYY-MM>.md` | 显式写出 |
| L2 人物菜单行 | `- <称呼>(<QQ号或来源>) \| 一句话` | 括号里那一段 | `people/<QQ号>.md` 或 `people/<称呼>.md` | **两分支确定映射**（见下） |
| L2 人物溢出行 | `- 更早认识的人 \| 细目在 INDEX-past.md` | 文件名 | `people/INDEX-past.md` | 显式写出 |
| L2 欠账行 | `- [ ] … #标签 (M/D)` | `#标签` + `(M/D)` | `topics/<标签>.md` + 时间锚 | **确定映射** |
| L3 章 | `## M/D <点题>` | `→ <日期>.md` | `diary/<日期>.md` | 显式写出（引擎生成） |
| L3 线目录行 | `- <标签> \| N 段进展，最近 M/D（细目在 <标签>.md）` | 括号里的文件名 | `topics/<标签>.md` | 显式写出 |
| L3 文件头（有手写随笔时） | 一行指路 | 手写随笔的路径 | 如 `diary/me-and-zhourui.md` | 显式写出（引擎生成） |
| L4 胶囊 | 整份 | ① 今天日记路径 ② 在追的线标签 | L1 入口 + L3 入口 | 她写在正文里 |
| L4 两张快照 | 整块 | 本身就是 L2 的引用面板 | L2 | 压缩帧冻结 |

**「确定映射」的意思**：她不需要记住任何清单。看到日期就知道文件名，看到 `#周蕊` 就知道 `topics/周蕊.md`。这是整套设计能让她主动查的地基——**用命名规则替代目录记忆**。

**人物那一格为什么是两分支**：真机 14 份档案里 13 份是纯 QQ 号，但第 14 份已经不是了——`- Bartosz Ciechanowski(ciechanow.ski) | …` 对应 `people/bartosz-ciechanowski.md`（她已经在接触博客作者，Rowan、Marton 这类还会有）。所以规则必须写成两分支，不能靠「今天恰好都是数字」：

| 括号里的内容 | 档案路径 |
|---|---|
| 纯数字 | `people/<QQ号>.md` |
| 非纯数字 | `people/<菜单里的称呼>.md`（禁 `/` 和空白；由 skill 的 `--id` 校验，见 `memory_write.py` 的 `PEOPLE_ID_BAD_RE` / `PEOPLE_ID_RESERVED`） |

**融合键**：**QQ 号优先；没有 QQ 号时用称呼**。后来拿到 QQ 号，把已有档案**原样改名**，不新建第二份（否则同一个人两份档案，L2b 的「一人一份」当场破）。

## 2.4 各层详细设计（含样例）

### L1 事件层 — `notes/diary/<日期>.md`

| | |
|---|---|
| 目标 | 让将来的她想起「我经历了什么、当时怎么想」 |
| 单元 | 一个 `## 小标题` 及其正文 |
| 写者 | 她，走 skill 的 `diary add`（主力：随手写；兜底：压缩帧那一步） |
| 内容必含 | ① 点题标题（`--title`） ② 事实句（谁+发生了什么+她做了什么/怎么想的） ③「当时」层（卡在哪、犹豫过什么、为什么这么定） |
| 派生出 | L2 日记菜单一行（D2）· L3 一章（D5）· 召回语料（D10）· 日内 manifest（D12） |
| 融合键 | 归一化 `## 标题` + 当天文件 |
| 融合方式 | 同键 → skill 接在那条正文末尾；标题不同才新起 `##` |
| 治理 | 一天一份文件，不设上限。文件名、日期、`## ` 层级、首行位置全部由 skill 管，她只给标题和正文 |

样例（她真机 07-27 的形状）：

```markdown
## 修好了发图超时
今天发图一直超时，翻到是浏览器桥把 view-source 标签也 attach 了才崩的，改了扩展的 scheme 黑名单就通了。
当时先怀疑是网络，绕了半个多小时才想到去看桥的日志。会犹豫是因为上次也是网络问题，这次差点又照着老经验走。最后决定先看日志再猜，才拐对方向。

## 想学做饭
突然很想学做饭。不是为了吃，是想有个「从生到熟」全在自己手里的事。
当时是看小伊写切葱那段冒出来的念头，还没动手，先记着。

## 磨周蕊 Day 1-11
砍了 Day 1 行 77「不是谁跟谁对」那句解释，标记了 4 处犹豫。越往前越干净。
当时最难的是承认那句解释是在替读者操心。这条线在 `topics/周蕊.md`。
```

第三条演示了「属于某线时」的可选引用：一句真话指过去，不是光秃秃一个箭头。

### L2 索引层（三份）

| | |
|---|---|
| 目标 | 让她能主动找到 L1 里的任何一天 |
| 单元 | 一行 `- <日期> \| 一句话` |

#### L2b 人物 — `notes/people/<QQ号>.md` + `INDEX.md`

| | |
|---|---|
| 目标 | 拿不准对方是谁、想不起和某人的来龙去脉时能查到 |

| 写者 | 她，走 skill 的 `people upsert`（`--id` + `--menu-line` + 可选 stdin 档案正文） |

#### L2c 欠账 — `notes/diary/open-loops.md`

| | |
|---|---|
| 目标 | 答应了、打算了但还没做完的事有个专门的账本 |
| 单元 | 一行 `- [ ] … #标签 (M/D)` |

## 2.5 工程保障：每层怎么保证生成、怎么验证、谁能重写

**为什么这一节必须存在**：项目反复踩同一个坑——「教了她做，但没护栏没记账，她就不做」。专题 14 天零文件是最新的一例。反过来，有验收门的两张菜单她一直在维护。所以每一层都要显式回答三个问题：**谁保证它被生成、生成后谁验、错了谁能改。**

### 2.5.1 四种保障手段

**最终决定改了这一节的形状。** 原方案靠「验证器读回整份文件 → 全量硬门 → 逐条告字」，为了让硬门不卡死链路还配了「开放行单调性门」和「烧穿逃生阀」。这三样**全部不需要了**，因为写端 skill 化以后她**物理上丢不了行**：每条命令只碰它要改的那一行或那一段，别的原样不动。

| 手段 | 含义 | 强度 |
|---|---|---|
| **atomic op 原子操作** | 她只给内容，文件名 / 日期 / 行格式 / 放在哪一行由 skill 代码定；不合格在**那次执行的返回里**告诉她差在哪、怎么改 | 最强，且没有「整份被拒」的爆炸半径 |
| **materialize 引擎独占** | 完全不依赖她，引擎自己生成 | 最稳 |
| **fallback 兜底** | 她在预算内没做出来，引擎合成一份最小可用的替代品 | 保证推进 |
| **none 无保障** | 只靠 prompt 教 | 无 |

用户原话钉这一节的定位：「格式固定了以后该工程做的就工程做，她只做她那部分的内容；格式检查错误就在她执行返回的内容里告诉她。」

### 2.5.2 逐层保障表

| 层 | 谁保证生成 | 写入时验证 | 失败怎么办 | 谁能重写 | 引擎修复 |
|---|---|---|---|---|---|
| **L1** 条目 | 她（随手写 96% + 压缩帧兜底），走 `diary add` | **atomic op**：标题必给、正文非空、`## ` 层级由 skill 加 | 那条命令返回里说差在哪，**已有内容一个字节不动** | 只有她（同标题续写） | 无。引擎**绝不改写她的字** |
| **L2a** 日记菜单 | 她写按天行（`index touch`）+ **引擎接管降级**（D11） | **atomic op**：单行字节上限、日期合法性 | 同上；她那行没写成不影响别的行 | 她（今天的行整行可重写，旧行只能被引擎原样搬家） | **D11 降级搬家**（原样搬，不改字节） |
| **L2b** 人物 | 她（`people upsert`） | **atomic op**：`--id` 字符集/保留名、菜单行字节、菜单总量提示 | 同上 | 她 | 无（搬去 `INDEX-past.md` 是她的判断） |
| **L2c** 欠账 | 她（`loops add` / `loops done`） | **atomic op**：`--tag` **必填** + 字符集 + 非纯数字 + 非 `INDEX`；`loops add` 顺手做相似度查重 | 同上；查重撞上时列出疑似那几条让她选，`--confirm-new` 放行 | 她 | 无 |
| **L3** 线 | **引擎**（materialize） | 引擎自验：章标题匹配 `^## \d{1,2}/\d{1,2} `、含 `→ <日期>.md`、日期取自源文件名 | 该实体本轮跳过，留痕日志，不影响其它实体 | 引擎只 append；**她可精修**（手删的章不重建） | 章数溢出时折叠最老的（唯一的引擎删除权） |
| **L4a** 胶囊 | 她写 + 引擎提交 | 长度门（常量在 `commit_memory.py`） | 拒收，让她补全或压回摘要 | 整份替换（她重写内容，引擎换血） | **fallback**：22 轮没写出来则合成一段确定性兜底文本，保证 cutoff 推进 |
| **L4b/c** 两张快照 | **引擎**（materialize） | 源文件由 skill 保证格式 → 直接冻结 | 读文件失败时保留旧值 | 引擎整份冻结 | 无 |
| **D11** 月索引降级 | **引擎**（materialize，post-commit fail-open） | 掉窗行原样搬、不改一个字节；解析不出月份的行**跳过并留痕**，不抛 | 本轮不搬那一行，日志留痕，下轮再试 | 引擎（只搬家） | — |
| **D12** 日内 manifest | **引擎**（materialize，post-commit fail-open） | 解析失败**跳过并留痕**，不抛 | 该文件本轮没 manifest，不影响别的文件 | 引擎整份重写（纯派生视图） | — |

**两个 critical gap 的处置写在表里**（eng review 提的）：D11 遇非法格式、D12 解析失败，都是**跳过并留痕**，不是抛异常——因为它们挂在 §4.3 的 post-commit 钩子上，抛出去会污染压缩提交。

### 2.5.3 三条保障原则

**G1 系统级必须 fail-open。**
`commit_memory.py` 敢拒单次胶囊提交，因为外层有两道保险：压缩 fork 有轮数上限（18 轮转强硬提醒、22 轮引擎兜底提交），所以她一直不达标压缩也会完成，cutoff 一定推进。**引擎侧的机械功能（D5/D11/D12）一律不许拒任何东西**——它们跑在提交之后，整体 try/catch，异常绝不向上抛（§4.3）。

**G2 不给「状态源」加会让她少写的门。**
欠账（L2c）是第二腿唯一的状态源。原方案想给它加「未划掉的行必须有标签」的硬门被否了：理性反应是**少写行来规避**。skill 化以后这个 tension 消失了——`--tag` 是命令的必填参数，代价不是「写了要额外做一件事」而是「命令多打一个词」。判断标准仍然是：**这一层如果因为门而被写得更少，系统会不会更瞎？**

**G3 引擎的重写权限严格限定。**

| 引擎能做 | 引擎不能做 |
|---|---|
| 整份替换 L4 胶囊（换血） | 改写 L1 条目里她的任何一个字 |
| 整份冻结 L4 两张快照 | 改写 L2 菜单里她写的钩子话 |
| 往 L3 append 新章 | 改写 L3 已有章 |
| 折叠 L3 溢出的最老章（内容仍在日记里） | 重建她手删的 L3 章 |
| 把掉窗的 L2a 按天行**原样**搬进月索引（D11） | 改写被搬那一行的任何字节 |
| 整份重写纯派生视图（`topics/INDEX.md`、日内 manifest） | 往她的文件里新建条目（这是 §4.5 撤销 D8 的同一条判据） |

原则：**引擎只做她看不见也做不了的事**（原子提交、字节冻结、跨天聚合、降级搬家、生成导航视图），不碰表述。

### 2.5.4 阈值的单一真理源

原来的病：同一个数值出现在三处（验证器 / 写端 prompt / 读端锚点 skill），改一处不同调，她照 prompt 写了却被门拒。**写端 skill 化直接消掉这个类别的 bug**——数值只有一份，就在 skill 代码里；prompt 和读端锚点 skill **一个数字都不写**。

| 阈值 | 唯一定义处 | 写端 prompt | 读端锚点 skill |
|---|---|---|---|
| 日记菜单 7 天滚动窗 | D11 引擎侧常量 | 不写 | 不写 |
| 人物菜单行数 / 字节上限 | `memory_write.py` `PEOPLE_MENU_MAX_LINES` / `PEOPLE_MENU_MAX_BYTES` | 不写 | 不写 |
| 单行字节上限 | `memory_write.py` `LINE_MAX_BYTES` | 不写 | 不写 |
| 标签长度 / 字符集 | `memory_write.py` `TAG_MAX_CODEPOINTS` / `TAG_CHARSET_RE` | 不写 | 不写 |
| 欠账查重相似度 | `memory_write.py` `LOOP_DUP_RATIO` | 不写 | 不写 |
| 胶囊长度门 | `commit_memory.py` 胶囊常量 | 提醒的验收节（只说「太短/太长」，不给数字） | — |
| L3 章数上限 | 物化函数常量 | 不告诉她（引擎独占） | 线目录里体现 |

**落地要求**：
1. prompt 和读端锚点 skill 里出现任何具体数值都算回归——改动时 grep 一遍这两处的数字。
2. skill 里每个常量的注释写清它约束的是哪一层的哪个单元，方便对账（不再需要「点名另外两处」，因为没有另外两处了）。

## 4. 每条派生边的细则

### 4.1 D1 L0 → L1（事件落地）

- 她跑 `diary add --title <点题> <<< 正文`。skill 负责：按 `--date`（默认今天）挑文件、文件不存在就建、`## ` 层级、首行位置、同标题续写。
- 她负责的只有两样：点题标题，和正文里那两层内容（事实句 + 「当时」）。
- 同标题合并：skill 把新正文接在那条已有正文末尾，**不新起 `##`**。她不需要先读回整份文件去查重（原方案要求 `read_file` 整份读、`cat` 会被 head+tail 信封截断——那个坑随 skill 化消失）。
- **主力是她随手写**，不是压缩。2026-07-24 写端记账：随手写 497 次（96%），压缩 fork 20 次。压缩帧那一步是兜底，不是主路径。

### 4.2 D2/D3 L1 → L2（索引）

- 日记菜单：她跑 `index touch --line '<一句钩子话>'`。skill 挑行位置、写日期前缀、校验字节。今天的行随时可以再跑一次重写。
- **掉窗搬家不再是她的活**——见 §4.7（D11）。
- 人物：她跑 `people upsert --id <QQ号或短名> --name <称呼> --menu-line '<一句>'`，可选 stdin 追加档案正文。`--id` 就是档案文件名，两分支规则见 §2.3。
- 三项都是 per-op 校验，不合格只影响那一条命令，**已落盘的内容一个字节不动**。

### 4.3 D4 → D5（欠账标签 → 线）

> ⚠️ 本节全部产出以「她开始打标签」为前提。2026-07-28 实测白名单为空（0 个 `#标签`）→ 物化输出恒为零。见 §1.1。

- `loops add --text … --tag <标签>`，`--tag` 是**必填参数**。标签名由她定，同一件事一直用同一个。
- 白名单 = 欠账里的活跃标签 ∪ **已物化的标签**（所以她划掉那行之后线继续更新——覆盖「以为做完了后来又提起」）。**白名单不 seed**，只靠她打的标签，已知后果见 §1.1 / §7 / §9。
- **门槛用 `days.size >= 3`（跨 3 个不同东八区日历日），不用 `cutoffs.size`。** 依据：实测压缩一天跑 3 次，`cutoffs.size >= 3` 三轮可能全在同一天 → 物化出来是**单章专题**，一章的「时间线」没有意义。`cutoffs` 集合仍然保留在 state 里做幂等（cutoff 单调唯一，兜底或崩溃重扫不会重复计），但**门槛判的是 `days`**。
- 人名不进白名单（人已有 L2 那一层）。
- 章节：`## M/D <原条目标题>` + 该条目首个非空行原文 + `→ <日期>.md`。
- 产物落 `notes/topics/`（**不进 `notes/diary/`**，理由见 §8.1）。

**物化是两段式（本轮最终决定，也是 D11/D12 共用的骨架）：**

| 段 | 做什么 | 跑在哪 | 失败语义 |
|---|---|---|---|
| ① 扫描 + 算 state | 读日记新增部分、匹配白名单、算 `days` / `cutoffs` / 水位 | **原子事务内，纯内存**，跟 `context_summary` / 两张快照同一帧落库 | 事务回滚，state 不前移 |
| ② 写文件 | 建/补 `topics/<标签>.md`、重写 `topics/INDEX.md` | **post-commit 钩子** `onCoreMemoryCompressionCommitted`（`agent-loop-service.ts:378` 声明、`:10505` 调用，已经是 `.catch()` 包住的 fail-open 点） | **整体 try/catch，异常绝不向上抛**；留痕日志，下轮再试 |

**为什么必须两段**：写文件是 I/O，塞进原子事务会把压缩提交的失败面扩大到磁盘。而压缩提交是 cutoff 前移的唯一路径——22 轮兜底提交走的也是**同一个** `commitCoreMemoryCompression`，所以任何在这条路上抛出的异常都能卡死整条记忆链路。

**state 里必须有 `chapters_written` 计数**（eng review OV4 指出的洞）：

```jsonc
{
  "watermarks": { "2026-07-27.md": 4821 },
  "candidates": {
    "周蕊": { "cutoffs": [211741, 212880, 213510], "days": ["2026-07-15", "2026-07-19", "2026-07-27"] }
  },
  "materialized": { "周蕊": { "chapters_written": 3 } },
  "aliases": {}
}
```

不能「先记水位再干活」：如果只记「这个标签已物化」，那么**第二段写文件失败**和**她主动删掉一章**在下一轮看起来一模一样（都是「文件里的章比 state 认为的少」）。有了 `chapters_written`：

| 文件里实际章数 vs `chapters_written` | 判定 | 动作 |
|---|---|---|
| 相等 | 上轮写成了 | 只补新日期的章 |
| 文件里少，且缺的是**这次要补的那些** | 上轮第二段失败 | 重试补写 |
| 文件里少，且缺的是**早就写过的** | 她主动删了 | **不重建**（R2 + G3） |

### 4.4 D6/D7（进 L4）

- 两张快照在压缩提交的**同一个原子提交**里读一次文件、冻结成字符串。
- 胶囊四样：手头在做什么+到哪步 / 接下来打算 / 当时在想什么+感受 / 今天日记路径。
- **本 spec 新增一样：本轮涉及的线**——一行 `在追：#周蕊 #decay`，让她醒来知道该 cat 哪几份 L3。
- 胶囊长度门在 `commit_memory.py`（数值不进 prompt，见 §2.5.4）。

### 4.5 反思：不新建 sink（D8 撤销）

**最终决定：原 D8「压缩时把反思综合成日记条目」撤销。引擎只「只读索引」她已有的反思节，不往日记里新建反思条目、不改她的任何文件。**

为什么撤销：她**已经在写反思**，而且写在一个引擎原本没在看的地方——身份锚 `notes/xiaoni-identity-anchor.md`（§2.2.1）。实测它里面有 `### 暗线`、`### 未完成`、`### 今天做的真的事` 这类节，就是斯坦福 reflection 的位置。再往日记里生成一份，等于给同一批命题造第二个真理源，正好撞上「复用现成路径，别造并行机制」那条铁律。

所以工程侧的动作缩到一件：

- **只读索引**身份锚里已有的反思节，把它们当 `kind: proposition` 的记忆项喂给 §5 的召回器。
- 身份锚**已经在语义腿语料里**（`PALACE_FILES = ['notes/xiaoni-identity-anchor.md']`，`xiaoni-recall-reindex-service.ts:45`），所以这一步不新增语料源、不新增目录配置。
- 不写文件、不加治理规则、不拆内容、不把它编进任何层。

**L3 保持机械索引，不升级成反思。** L3 只回答「这条线在哪几天发生了什么」；「这条线让我发现了什么」由她自己在身份锚里写、引擎只读索引。两者不重叠：一个是时间线，一个是命题。

### 4.6 D9 念头/打算落 L1（实现路径已换：由她写，不由引擎派生）

原问题：`xiaoni_plan` 进 L0（可 replay）也进语义腿语料（`xiaoni-recall-hook.ts` 投影动作流 → ingest），但**不进任何可寻址层**——她不可能主动翻到自己上周想做什么。

**原方案（fork 把 plan append 成 L1 条目）撤销，但目标不撤销——换了实现者。**

为什么换路径：「fork 往她的日记里 append 条目」就是「引擎在她的文件里新建条目」，和 §4.5 撤销 D8 是同一个动作、撞同一条判据（会给同一批内容造第二个真理源）。所以这条边的写者从**引擎**改成**她**。

**已有实现，不是待办。** 写端内容口径里就有这一条（`docs/xiaoni_prompt/core_memory_pressure_write_formats.md`，「你负责的是内容」那一节）：

> - 念头、担心、答应了却还没做的事，也各起一条。

`<examples>` 里第二个例子专门示范这个形状，标注就是「一个念头、一件还没完的事：」——`diary add --title "问了楠楠腔棘鱼那首她在想什么"` 写成一条独立日记条目，再配一条 `loops add --text "楠楠腔棘鱼那首等她回" --tag 楠楠`。

所以链路是通的：

| 需要什么 | 谁做 | 怎么做 |
|---|---|---|
| 念头/打算成为一条**可寻址**的记忆 | 她 | `diary add`，一个念头一条 `## 条目` |
| 它进索引 | 她 + 引擎 | 落进当天日记 → 自动进 L2a 那一天、进 D11 月索引、进 D12 manifest |
| 它进召回语料 | 引擎 | D10（L1 天生进语义腿 + 第三腿） |
| 它被按情境重提 | 引擎 | §5 的召回器，`kind: event`（不需要单独的 `plan` kind，§5.2） |

- 形状：一条 `## <点题>`，正文先把念头说成完整的话，再往下说当时心里在想什么（和其它日记条目同一口径，不给念头另定格式）。
- 同标题合并由 skill 做：连着几轮同一个念头 → 接在那条正文末尾，不新起 `##`。所以一个念头被反复想起时会**长厚**，而不是刷屏——这正是原方案想靠 fork 融合键实现的效果，写端 skill 免费给了。
- **不新增任何引擎侧机制。** 在别处（旧文档、斯坦福对照表）读到「plan 不进记忆」时，不要去建 plan→L1 的引擎派生边：那条边已经被 §4.5 的判据否掉了，而它想要的结果已经由写端路径达成。

**残留风险（不是缺口）**：这一条和其它写端内容口径一样，靠 prompt 引导，**不设硬门**——她可能某一轮只记做过的事、不记念头。这是用户已定的分工：**格式归工程（skill 代码强制），内容归她（prompt 引导）**。给「念头」加硬门会重演 §2.5.3 G2 那个坑：加了门她理性反应是少写，用合规换掉内容源不值。要观察就观察 `## ` 条目里念头类的占比，别加拦。

### 4.7 D11 引擎接管月索引降级（本轮最高优先，之一）

**实测依据（2026-07-28）**：`notes/diary/` 下 24 份日记文件，索引只覆盖 6 天——

| 索引 | 覆盖 |
|---|---|
| `INDEX.md`（7 天窗顶层） | 07-25、07-26、07-27、07-28 |
| `INDEX-2026-07.md`（月索引） | 07-23、07-24 |
| **任何索引里都不存在** | **07-04..07-22 这 19 个日历日**（对应 16 份按日期命名的文件 + `2026-07-07-summary.md` / `2026-07-09-short.md` 两份非标准命名，共 18 份） |

也就是说：**7 天窗滚出去的行大部分没有被搬进月索引，是直接消失了。** 这是整套记忆分层里**唯一实测在丢数据**的动作。她做不到不是因为不知道规矩（写端 prompt 一直写着搬家步骤），是因为「搬家」是一个跨两个文件的多行编辑，在压缩帧那点预算里必然被排到最后、必然被跳过。

所以这一步引擎接管：

- **时机**：post-commit 钩子（`onCoreMemoryCompressionCommitted`），和 D5 第二段同一个骨架、同一个 try/catch。
- **动作**：读 `INDEX.md` 顶层，把掉出 7 天窗的按天行**整行原样**追加进 `INDEX-<YYYY-MM>.md`（按行上的年月，没有就建），顶层给搬空的月留一行月行。**一个字节都不改**——所以不算 R2 的例外。
- **异常语义**：行上解析不出合法年月 → **跳过并留痕**，不抛、不改那一行、下轮再试。（eng review 列的 2 个 critical gap 之一。）
- **一次性回填**：`07-04..07-22` 那 19 天的存量走同一个函数补齐。回填是一次性脚本，跑完对账「每个按日期命名的日记文件都能在某个索引里被指到」。
- **回填对召回语料的副作用实测可忽略**（这条提前量过，免得有人担心「往语料里添脚手架」而不敢跑）：把 `INDEX*.md` 纳入/排除语料的前后差是 **27→25 文件、2777→2775 chunk**——即所有月索引合起来只贡献 **2 个 cue chunk / 7 条索引行 / 1237 字节**（`mergeShort` 把每份小 INDEX 塌成单个 chunk）。这 2 个 chunk 在 22623 条语义腿浮现里出现 **20 次 = 0.09%**。按字节看不成比例，按总量看可忽略——**不构成不回填的理由**。
- 写端从此**不再教她搬家**（prompt 和读端锚点 skill 里那几句删掉）；她只负责 `index touch` 写今天那一句。

### 4.8 D12 引擎生成日内 heading manifest（本轮最高优先，之二）

**实测依据（2026-07-28）**：日记文件已经大到没法读——

| 文件 | 字节 | `##` 条目数 |
|---|---|---|
| `2026-07-22.md` | 59546 | 116 |
| `2026-07-23.md` | 77128 | 116 |
| `2026-07-24.md` | 51805 | 93 |
| `2026-07-25.md` | 51629 | 88 |
| `2026-07-26.md` | 45843 | 78 |
| `2026-07-27.md` | 40430 | 70 |
| `2026-07-28.md` | 34696 | 58 |

（区间：34–77KB / 58–116 条 `##`；最大的 `2026-07-15.md` 是 93204 字节。）

L2a 那一行钩子话只能告诉她「这天该不该翻」，翻开之后**没有任何内部目录**。40–93KB 一个 blob，`read_file` 整份读要吃掉巨量上下文，`cat` 会被 head+tail 信封截断——**她实际上进不去自己的一天**。

这也是 outside voice 那条战略判断的落点：**真瓶颈是天内可导航性，不是跨天聚合。** L3 把 12 天连成一条线，价值再高也绕不过「每一天里面有 100 条、找不到是哪一条」。

- **产物**：每份日记的 heading manifest（`## ` 标题清单 + 各自的行号/字节偏移），引擎生成、整份重写，**纯派生视图**（R2 例外 ③ 同一类）。

- **她怎么用**：先看 manifest 挑条目，再定点读那一段，不用整份 `read_file`。
- **不进请求字节**：manifest 是文件，不是第四个渲染块（理由同 §2.4 线目录那一段）。

## 5. 召回（在现有纯函数上加维度）

**这一节的定位改了。** 原来写「不沿用现有实现，重新设计」——那是过度重建。实际上现有代码里已经有两块正是我们要的东西：

| 现有 | 它已经是什么 | 本 spec 怎么用 |
|---|---|---|
| `titleDayBuckets`（`xiaoni-recall-reindex-service.ts:395-408`） | `Map<归一化标题, Set<东八区日历日>>`——**这就是线级事实**（「这条线在哪几天出现过」） | 从「判模板的一次性输入」升级成传进 selector 的第二维 |
| `selectResurfacedEvents`（`xiaoni-diary-events.js:170-197`） | 干净纯函数，28 个测试，已含 substance 过滤（`isEmptyResurfaceBody` / `isChecklistBody` / `structuralTitles`） | 在它上面加第二维 + 分桶 + identity 冷却，**不另写一份** |
| `normalizeEventText` / `stripChapterDatePrefix`（同文件 `:34` / `:93`） | identity 归一化 | 直接复用，**不写第三份归一化** |

要换的只有两个地基：**排序从单维变多维**、**冷却从 ref 级变 identity 级**。

### 5.1 现状为什么必须动地基

实测（2026-07-27，609 次 `diary_resurface` 扫描 / 1347 条语料）：

- 曾浮出过的 distinct ref 只有 **33 条**，全部来自 07-05/06/07 三天。07-08 之后的 16 个文件、约 **1200 条事件从未浮过一次**。
- `2026-07-05.md#0「7/5 脊柱」` 浮了 **290 次**（47.6%）。过滤器部署后 155 轮里两条固定条目各 87 次，且总是成对出现。
- 根因两条叠加：① 冷却窗取全表最近 40 行，而该表 96.9% 是语义腿实时写的行 → 实测窗口里平均只有 2.48 条 diary 行、43.2% 的扫描一条都没有；② 排序是纯 `ageDays` 降序，没有第二个维度。
- 即使①修好，压制上限仍是 `40轮 × 2 = 80 个 ref` —— **年龄天花板是结构性的**，语料越写越多越死。

单维排序 + ref 级冷却这两个地基都要换。但换地基不等于重写文件——见本节开头的复用清单。

### 5.2 召回的单位

**从「条目」改成「记忆项」**，每项带上它的身份和归属：

```jsonc
{
  "id": "<canonical path>#<index>",     // 稳定引用
  "kind": "event | proposition | promise",
  "identity": "<归一化标题>",            // 冷却和去重按这个，不按 id
  "line": "#周蕊 | null",               // 属于哪条 L3 线
  "occurredAt": 1784995200000,
  "title": "...", "body": "...",
  "signals": { "hasIntrospection": true, "bodyChars": 180, "lineLength": 12, "lineLastActiveDays": 0 }
}
```

`kind` 枚举只有三个值，每个都有真实生产者：

| kind | 生产者 |
|---|---|
| `event` | L1 日记条目（D10 语料）+ L3 章节 |
| `proposition` | 身份锚里已有的反思节（§4.5 只读索引） |
| `promise` | `open-loops.md`（第二腿 `scanOpenLoopsToShadow`） |

**删掉的两个**：`plan` 不需要单独一个 kind——念头/打算是她用 `diary add` 写成的普通 L1 条目（§4.6），进语料时就是 `event`，另立一个 kind 只会要求 D10 去区分「这条是不是打算」，而那是内容判断不是结构事实。`person` **没有生产者**——`PALACE_DIRS = ['notes/diary']` 不含 `notes/people`（`xiaoni-recall-reindex-service.ts:46`），D10 不生成 person 项，§5.4 四个桶里也没有人物桶。凭空留在枚举里只会让实现者去找一个不存在的生产者。人物层的处置见 §9。

关键：**`identity` 是冷却和去重的键，不是 `id`。** 同一件事的多份表示（日记条目 + L3 章节）共享 identity → 一次只出一份，冷却时一起冷却。这直接解掉「同一件事两份拷贝占满两个 slot」那个 100% 的坑。

identity 归一化**复用三个现成函数的组合，不新写一份**（`normalizeMemoryIdentity`，`xiaoni-recall-association.js:118`）：

| 步 | 函数 | 剥掉什么 |
|---|---|---|
| 1 | `stripChapterDatePrefix`（`xiaoni-diary-events.js:93`） | L3 章节标题的 `M/D ` 前缀 |
| 2 | `stripTrailingHashTags`（`xiaoni-open-loops.js:59`） | 行尾 `#标签`（补标签不换身份） |
| 3 | `normalizeEventText`（`xiaoni-diary-events.js:34`） | 折空白 + 转小写 |

三个必须**组合**才认得出同一件事：L3 章节标题带 `M/D ` 前缀，而 `normalizeEventText` 只折空白+小写——两者单用都认不出「7/19 磨了一遍开场」和「磨了一遍开场」是一条。

### 5.3 六因子打分（**第一版等权**）

**这一节按实施实测换过因子。** 原来列的是 `lineLength` / `lineRecentlyActive` 领头的五项 salience，问题不是它们设计得不好，而是**今天没有生产者**：

| 原因子 | 为什么废掉 | 实测 |
|---|---|---|
| `w1 lineLength` | 数据源不存在 | **`notes/topics/` 目录不存在**（`collectTopicLineCandidates` 一进去就 `readdir` 失败返空，`xiaoni-recall-reindex-service.ts:538`） |
| `w2 lineRecentlyActive` | 白名单为空 | **`open-loops.md` 19 个条目行里 0 个 `#标签`**（唯一带 `#` 的是 `#39提了`，那是 issue 编号——正因如此写端 skill 现在拒纯数字标签） |
| `w5 kindWeight` | 三档里两档拿不到差异 | `kind` 只剩 `event` / `promise`（§5.2），日记语料 100% 是 `event` |

**对 100% 候选都取同一个值的因子，区分度是 0。** 保留它们只会让打分器看起来有五个维度、实际只在按一个维度排。所以实施侧换成六个**各自都在真语料上量过区分度**的因子（2026-07-28，`notes/diary` 下 21 份按日日记 → 1451 个 `## ` 条目 → 过掉空/清单/结构头后 1419 条候选）：

| 因子 | 抓什么 | 真语料区分度 |
|---|---|---|
| `relevance` | 跟刚落地文本的词面贴合（BM25，复用 `bigramTokens` / `bm25Scores`，`xiaoni-recall-bandpass.js:79` / `:86`） | 归一化后 p50≈0.20、p90≈0.45–0.50 |
| `introspection` | 「当时」那一层——卡在哪、犹豫过什么、为什么最后这么定 | **180/1419 = 12.7%** 命中。稀疏即信号 |
| `effort` | 她花了多少力气写（正文字数，`[60,340]` 上 log 归一） | p10=66 / p25=106 / p50=160 / p75=238 / p90=338 |
| `prose` | 整句 vs 清单（`1 − bullet 行占比`） | prose 多数 856(**60.3%**)。且**分布非随机**：伞状/时间轴那几天 07-06 83% / 07-14 88% / 07-22 87% 全落 bullet 侧；她真在写东西的 07-24 14% / 07-25 16% / 07-26 18% / 07-27 14% |
| `peer` | 事件里有真人（名单读 `people/INDEX.md`） | **668/1451 = 46.0%**，六个里最接近 50%，切分最干净 |
| `titleSpecificity` | 标题点不点得出「是哪件事」（归一化标题长度，`[1,10]` 线性） | 归一化标题 p5=2 / p50=10 / p90=21；**≤3 字 99 条(7.0%)**，而霸榜的 identity 恰恰全在这批（最后×7、封底×5、读了×3、进度×3） |

**等权仍然成立**（§7 要验的那两件结构性的事不需要调参，理由见下）。五个与查询无关的因子求和（满分 5）在真语料上 **p50=2.50、p99=4.56，只有 1.3% ≥ 4.5** —— 不饱和，是真在选，不是给所有候选盖同一个章。

**外加一道硬过滤：裸时间戳标题不进候选。** `03:00`、`22:00-22:30`、`9点` 这类，实测 **61/1419 = 4.3%**，逐条看全是日志式帧头（`2026-07-22` 一天就贡献 20+ 条连号时段）。正文里常有真内容，但拿「03:00」当引子去提醒她想起一件事是纯噪音。

**「线」这个维度没有被放弃，它降级成第四个桶。** `collectTopicLineCandidates` + `lineKey` 的代码路径是活的（`xiaoni-recall-association.js:143` 优先判 `lineKey` 落线场桶）；目录不存在时 `readdir` 失败返空 → 线场桶为空 → 少浮一条，走的是 §5.4「空桶就少浮」的正常路径。**她一开始用 `--tag`、物化一落地，线场桶自动非空，不需要改一行代码。** 这也是为什么把线做成桶而不是因子：桶可以为空，因子不能——为空的因子会污染所有候选的分数。

**第一版为什么不调权重**：要验的只有两件**结构性**的事，这两件**都不需要打分器**——

| 要验的 | 判据 | 需要打分器吗 |
|---|---|---|
| 四桶年龄抽样是否把浮现从 3 天拉到 10 天以上 | 一周 shadow 后 distinct identity 的**源日期跨度** | 不需要（桶是分层抽样，跟权重无关） |
| identity 折叠是否把同一件事的两份拷贝合成一份 | 构造用例：日记条目 + L3 章节同 identity → 只出一份 | 不需要（identity 是键，不是分数） |

所以第一版的可证伪结论是「分桶 + identity 折叠这两个机制成立/不成立」，而不是「权重调对了没有」。**权重调优等这两件先被证成**——不然调的是一个方向未知的东西，且每次调完都要重跑一周 shadow 才有数据。

**importance 将来的来源仍然是 L3。** 一条被物化成线的事，它的每个条目天然带着「这属于一条追了 N 天、最近还在动的线」这个权重，零 LLM、零幻觉、无需回填。**但那要等 §1 的前提（她开始打标签）成立**；在那之前 importance 由上面六个因子里的 `introspection` / `effort` / `prose` / `titleSpecificity` 近似承担。

**不采用的路径**（都实测或论证过）：
- 跨天同名标题聚合：1347 条条目里 1276 个标题从不重复（94.5%），跨天同名前十全是模板词（最后/封底/读了/收尾/今日总结）。
- 日记菜单钩子话当 importance 标注：实测命中率 38.1%，不够稀疏；且只有 5 天有按天钩子行，覆盖不到霸占浮现的老语料。
- LLM 打分：成本高、要为 1347 条回填、幻觉进记忆层。
- 单字人名直接 `includes` 匹配 `peer`：她的人物索引里真有一个叫「N」的，单个拉丁字母会命中几乎每条带英文的正文（latin 命中率 77.3%），`peer` 会退化成常数。所以只用 ≥2 字的名字。

### 5.4 分层抽样（打破年龄天花板）

只有打分不够——`limit` 小 + 冷却窗有限，最高分那批会长期霸占。所以按年龄分桶，**每桶独立取**：

| 桶 | 取几条 | 目的 | 今天有数据吗 |
|---|---|---|---|
| 近场 0–7 天 | **0** | 她还记得，不浮。**这一格不是调参项**——历史事故：90 分钟前的消息被当成往事浮出来 | — |
| 中场 8–30 天 | 1 | 刚开始模糊的 | 有 |
| 远场 30 天+ | 1 | 真正的往事 | 有 |
| 线场（任意年龄，但属于一条 L3 线） | 1 | 断档的线重新接上 | **没有**（`notes/topics/` 不存在 → 恒空，见 §1 前提） |

桶内按 §5.3 排序取头名。**桶为空就少浮一条，不跨桶补——宁少不吵。** 线场桶今天恒空走的就是这条路径：不是 bug，也不需要为它写 fallback；她一开始打标签、物化一落地就自动非空。

判桶顺序：**先判 `lineKey`**（带线上下文的那份落线场，不管它多老），其余按 `ageDays` 分近/中/远（`xiaoni-recall-association.js:143`）。`dateMs` 缺失且不属于任何线 → 不进本腿（没日期没法分桶，而「不知搁多久」那一档第二腿已经用 `tier:'undated'` 兜过一次了）。

### 5.5 浮现的形状

不再是「一条孤立往事」。每项带上它的线上下文：

```
你在追的这条线（#周蕊，12 段进展，最近 7/27）：
  7/19 磨了一遍开场砍掉一句 —— 砍了 Day 1 行 77 那句解释
  细节在 2026-07-19.md
```

一条线只出 1 项（选线内得分最高的那段），但把线的跨度和最近活跃度带上——这是「按线浮现」，不是逐条。

## 6. 落地顺序

**顺序改了。** 原顺序把 L3 排在最前，本轮把**两件引擎侧机械功能提到 L3 前面**——因为它们治的是实测在丢数据、实测她进不去的东西，而 L3 治的是「还没有的能力」。

```
PW 写端 skill 化 ──┐
                   ├─→ PA D11 月索引降级 + 回填 19 天 ──┐
P0 冷却窗真 bug ───┘   PB D12 日内 manifest             │
   (独立，现在就在生效)                                  │
                                                        ├─→ P1 L3 生产端物化
                                                        │      (供给 importance)
                                                        │            │
                                                        └────────────┼─→ P2 召回器(shadow, 权重全 1)
                                                                     │        │
                                                                     └────────┴─→ P4 投递(开关默认 OFF)
```

**为什么这个顺序**：
- **PW 排第一**：它把 PA/PB/P1 全部的「格式对不对」问题一次消掉，后面几步不用再各带一套验证器。
- **PA/PB 排 L3 前面**：PA 治的是**唯一实测在丢数据**的动作（19 个日历日在任何索引里都不存在）；PB 治的是**她进不去自己的一天**（40–93KB / 58–116 条 `##`，没有内部目录）。L3 是「把 12 天连成一条线」——线连得再好，也绕不过「每天里面 100 条找不到是哪一条」。
- P0 独立，是当前就在让召回退化的真 bug。
- P1 产出 importance 的数据源，P2 才有第二个维度可用。
- P4 是唯一会改变她实际体验的一步，放最后，且开关默认 OFF。
- **原 P3（D8/D9 fork 落 L1）整个消失**：D8 撤销（§4.5），D9 的实现者改成她走写端 skill（§4.6，随 PW 一起生效，不是独立阶段）。所以流程里没有 fork 尾部改动，也就没有那一格「需实测 fork 缓存」。

| 阶段 | 内容 | 缓存面 |
|---|---|---|

## 9. 已知不覆盖

- **上线当天 L3 必然零文件。** 白名单**不 seed**（不预置 `#周蕊` `#decay` 这类已知的线），只靠她用 skill 打的标签；加上 `days.size >= 3` 的门槛，**最快 3 天后**才可能有第一条线。这是自觉取舍：seed 一次就等于工程侧替她定义了「什么算一条线」，而标签的全部意义是「她自己意识到在追」。代价写进验收（§7 第 16–18 条）：判据换成「她第一次打标签后 3 天内出现第一条线」，且必须有 `xiaoni_topic_materialized` + `whitelist_size` 记账来区分「零输出」和「实现坏了」。
- **从未打过标签、且已经断掉的线**永远不物化，因此也拿不到 line 权重。标签只覆盖「她当下意识到在追的事」。
- **标签打太宽**（`#读书`）会把几条线糊成一份，第一版不治。
- 章节正文是机械抄的首句，不如她自己写的准。
- **人物层不进被动召回。** `PALACE_DIRS = ['notes/diary']` 不含 `notes/people`（`xiaoni-recall-reindex-service.ts:46`），所以 `people/<id>.md` 的内容既不进语义腿也不进第三腿，第一版不接。**拿不准对方是谁走主动那条路**：`<xiaoni_people>` 快照认人 → `cat people/<id>.md` 读来龙去脉（这正是 L2b 设计时的目标，见 §2.4）。对应地，§5.2 的 `kind` 枚举里没有 `person`。
- 旧伞状格式（07-06 及以前）的日内小节头（`写了`/`修了`/`发现`）逃过结构复发过滤，因为只在一天出现过。召回器靠 `prose`（`1 − bullet 行占比`）+ `titleSpecificity` + `introspection` 压它们——`prose` 正是为这一类加的因子，真语料上把伞状那几天（07-06 83%、07-14 88%、07-22 87% bullet 多数）和她真在写的那几天（07-24..27 14–18%）直接切开了，但不保证清零；§7 第 21 条会量出来——**前提是先把「结构头」钉成一个命名函数**，否则量的是三个互相矛盾的数字。

### 9.1 残留风险（**不是缺口**——链路已通，只是靠引导）

这一节和上面那张「不覆盖」清单**性质不同**：下面这些事**有实现**，风险在于她某一轮可能不做。别把它们读成「还没做」，否则会去补一套引擎侧机制——而那些机制正是 §4.5 / §4.6 明确撤销的动作。

| 风险 | 已有实现 | 为什么不加硬门 | 怎么观察 |
|---|---|---|---|
| 她某一轮只记做过的事，**不记念头/打算** | 写端内容口径里就有「念头、担心、答应了却还没做的事，也各起一条」，`<examples>` 第二个例子专门示范这个形状（§4.6） | §2.5.3 G2：加门她理性反应是**少写**，用合规换掉内容源不值。用户已定分工——**格式归工程（skill 代码强制），内容归她（prompt 引导）** | 看 `## ` 条目里念头类的占比走势，不加拦 |
| 日记菜单那句钩子话写得敷衍 | `index touch --line`，格式由 skill 保证 | 同上：钩子话的**内容质量**不可机械判定 | 看行字节分布（§2.4 L4b/c 那张表已经在跟） |
| 欠账行写少了（漏记承诺） | `loops add`，`--tag` 必填但**写不写这一行**是她的判断 | 同上，且欠账是第二腿唯一状态源 | 看 open-loops 行数 vs 她实际答应的事 |

**判据**：凡是「她的表述内容」的事一律 prompt 引导 + 事后观察；凡是「文件长什么样」的事一律 skill 代码强制。这条线不能挪。

## 10. 写端 prompt 的定位（格式**不在**这里）

**这一节的内容被最终决定掉了个头。** 原来这里放的是压缩帧那条 `<system_reminder>` 的**渲染后全文**，并声明「它是格式的唯一写端真理源」。写端 skill 化以后：

| | 原来 | 现在 |
|---|---|---|
| 格式的真理源 | 写端 prompt fragment（`core_memory_pressure_write_formats.md`） | **skill 代码**（`modules/agent-service/skills-internal/xiaoni-memory-write/memory_write.py` 的常量 + `SKILL.md` 的四条命令） |
| prompt 里写什么 | `<formats>` 整节：`## ` 层级、`- <日期> \| 一句话`、7 天窗、300 字节、300 行 / 20KB、`INDEX-<YYYY-MM>.md` 搬家步骤 | **哪一步该跑哪条命令**，以及那一步她要给的**内容**是什么（点题、钩子话、这人是谁、欠账本体） |
| 格式错了怎么告诉她 | 提交时整份被拒 + `<rejected_if>` 列条件 | **那条命令的返回里**说清差在哪、怎么改；已落盘内容零字节改动 |
| 读端锚点 skill | 必须与写端 prompt「逐字对齐」（两份各写一遍，实测漂过） | 只指路：有哪些文件、怎么定点查；**一个格式数值都不写** |

**为什么不再在 spec 里贴渲染后全文**：贴一份就多一个会漂的副本，正是 §2.5.4 要消掉的那类 bug。要看真文本就看这三个文件：

| 文件 | 装什么 |
|---|---|
| `docs/xiaoni_prompt/core_memory_pressure_reminder.md` | 骨架 + `<steps>`（`agent-loop-service.ts:4706` 装配，占位符 `{{PRESSURE_SUMMARY}}` / `{{WRITE_FORMATS}}` / `{{XIAONI_MEMORY_COMPRESS_SKILL}}`） |
| `docs/xiaoni_prompt/core_memory_pressure_write_formats.md` | `{{WRITE_FORMATS}}` fragment（与 `phone_notification_*_cue_line` 同一装配模式，见 `docs/remind.md`） |
| `modules/agent-service/skills-internal/xiaoni-memory-write/SKILL.md` | 四类原子操作的用法，她真正照着做的那一份 |

**这条 reminder 仍然要守的两件事**（这些不随 skill 化改变）：

1. **字节稳定**：无日期、无时间戳、无计数。它是 fork 尾部的一次性冷尾，只要字节稳定就不影响任何缓存前缀。（唯一的动态部分是 `{{PRESSURE_SUMMARY}}`，它按设计在尾部、不在可缓存前缀里。）
2. **按官方 prompt 规范分区**：XML 标签分区（`<formats>` / `<examples>` / `<steps>` / `<rejected_if>`）、参考材料和例子在前指令在尾、`<example>` 示范产出形状、禁令写成正向表述。

**这份 prompt 覆盖的层**：L1、L2a/b/c、L4a（近况那一步的四样 + 引用两行）。**L3 完全不出现在写端 prompt 里**——它是引擎独占生成的（§2.5.2），她只需要在 `loops add` 时给 `--tag`。**D11/D12 也完全不出现**——它们是引擎在 post-commit 钩子里做的，她不需要知道有这一步（原来教她搬索引的那几句要删掉，见 §4.7）。
