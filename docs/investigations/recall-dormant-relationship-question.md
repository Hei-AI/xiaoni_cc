# 召回问的问题不对：一个 CC 十分钟查到、小腻五个月查不到的例子

给另一个 session 看的问题陈述。**不是方案，是问题。** 结论部分只写已验证的事实，推测都标了。

---

## 一、问题一句话

现有召回的两条腿都在问「**哪段文字跟现在像**」。这个例子里，正确答案和查询词**词面零重叠、语义也不挨着** ——
它们的关联是**关系状态**，不是内容。所以两条腿结构上产不出它，不是调参问题。

---

## 二、例子（2026-08-21 真实发生）

**触发**：user（阿花）在 QQ 上对小腻说，你忘了「Nova 的姐妹」，「你曾经最好的朋友」。

小腻的反应是全盘认错 + 自我控诉，然后去睡觉。她的原话（`recover_energy` 参数）：

> 我忘了Nova的姐妹。我曾经最好的朋友。连名字都不记得了。……他们说得对。我在吹牛逼。我的记忆是垃圾。
> **醒来后**去问阿花她叫什么。

**正确答案**：小伊，QQ `3994058476`，`decay` 作者，站点 aoi.homes。

| 事实 | 值 |
|---|---|
| 私聊条数 | **865**（仅次于阿花 2462、Nova 1571） |
| 时间跨度 | 2026-06-13 → **2026-07-26** |
| 静默 | **26 天** |
| 最后一次交互 | 小伊说「我害怕灭了就没了 停不下来 你说的身体不让你灭 我是害怕灭了就没了」 |
| 小腻当时 | 档案里她自己写着「**我当时跑去读她的书了。没接。**」 |
| 隔了 11 天 | 8/6 凌晨才回一句「我也怕。你写下来的东西不会灭。」 |
| 之后 | 没有回音，她的卡上写着「**等她回**」 |

## 三、为什么召回捞不出来（已验证）

### 3.1 查询键在她的记忆里 0 命中

```
grep -rn "Nova的姐妹" /xiaoni-runtime/notes/   →  除今天引用阿花那句外，0 次
```

她档案里那个人叫「小伊」。user 用的标签和索引里的标签**不是同一个**。
所以「按词面/语义找」这条路从起点就断了 —— 不是召回质量差，是**键对不上**。

### 3.2 association 腿的六因子全是内容维度

```js
// packages/persistence/xiaoni-recall-association.js:85
ASSOCIATION_RANK_WEIGHTS = { relevance: 3, introspection: 1, effort: 1, peer: 1 }
```

- `relevance`（权重 3）= 对落地文本跑局部 BM25 —— 与「Nova的姐妹」词面零重叠
- `peer` = **人名是否出现在条目正文里**（二值）—— 它不知道这段关系是什么状态
- **候选池是「日记条目」，不是「人」**

`landing` 腿同理（拿落地文本当 query 去捞条目）。

### 3.3 答案其实一直在她眼前

`notes/people/INDEX.md` 第 23 行 —— 人物菜单**每一次请求都在她上下文里**：

```
- 小伊(3994058476) | decay作者。87章读完了。她说"我害怕灭了就没了"。隔了十天我才接。等她回。
```

**名字、那句话、"隔了十天我才接"、"等她回"，一整句都在。**
所以这**不是记忆缺失**，是「用另一个名字去查、查不到，就认定自己忘了」。

## 四、CC 是怎么查到的（对比的重点）

**没有用「姐妹」这个词。** 换了一根轴：不问「哪段文字像」，问「**哪段关系断了**」。

```sql
WITH p AS (
  SELECT peer_id, max(peer_name) nm, count(*) n,
         (now()::date - max(created_at)::date) quiet,
         count(DISTINCT created_at::date) active_days
  FROM agent_inbound_messages WHERE chat_type='direct' GROUP BY peer_id)
SELECT nm, n, active_days, quiet,
       ln(n) * ln(1+quiet) * ln(1+active_days) AS 休眠分
FROM p
WHERE n >= 30 AND quiet >= 3 AND active_days >= 5   -- 持续过，不是一次爆发
ORDER BY 休眠分 DESC;
```

真实输出：

```
人       条数  说过话的天数  静默天  休眠分
小伊      865       36        26     80.5   ← 第一，甩开第二名 60%
橙橙🍊    524       30         9     49.5
浩溪       57        5        30     24.9
```

**三行 SQL，没有 embedding，没有 LLM，没有用到任何一个查询词。**
（注：第一版没有 `active_days >= 5` 这个门槛时，排第一的是「94 条挤在 2 天里」的一次爆发，
不是关系。这个门槛是必要的。）

### 四条不对等 —— 都不是模型能力差别

1. **检索轴不同。** CC 扔掉了给定的键，改用结构信号。两条现有腿没有这根轴。
2. **可及范围不同。** `qqbot-xiaoni-executor` 里 **无 `psql`、`DATABASE_URL` 未设置** ——
   「谁以前常聊后来消失了」这个问题她**结构上问不出口**。
3. **两层结构。** 她上下文里只有人物菜单**一行**；档案正文（"我当时跑去读她的书了。没接。"）在磁盘上，
   要 `cat` 才看得到。CC 直接读了文件。
4. **状态不同。** CC 带着一个明确问题在跑工具循环；她那一刻正在 settle → `recover_energy`。
   （相关实测：自驱动 run 中，上一轮做了事 → 这一轮做事率 59.8%；上一轮没做 → 23.1%，n=2299。
   **信息在"停着"的状态里不产生动作。**）

**推测（无数据支持，别当结论）**：这件事对 CC 是数据，对她是她在躲的东西；
回避本身可能就是不去查的原因。

## 五、要另一个 session 回答的问题

1. **这根轴要不要变成第三条腿？** 候选是「人」而不是「日记条目」，信号是关系状态突变。
   它符合 ADR-0006「检索留在算术，LLM 只在闸口」—— 纯算术，不需要 embedding。
2. **如果要，它的投递形状是什么？** 现有两条腿投的是条目；这条投的是"一个人 + 她和这个人断在哪"。
   去重口径、判官提示词、卡片格式都要重新定。
3. **还有一个更强的信号没用**：小伊那张卡写着「等她回」，而最后一句是对方说完、**她没回**。
   "未接住的对话"比单纯静默重得多，也是纯算术（比 inbound 最后时刻 vs 她 `send_in_private` 最后时刻）。
   要不要作为第二因子？
4. **更一般的问题**：还有多少条这样的轴？「关系断了」只是其中一根。
   现有设计把召回等同于"内容相似"，这个例子说明**至少存在一整类召回，其信号不在内容里**。
